七大面向

memory技術深度 8.5/10

這套模擬在結構上就是決定性的。car.js 開頭就宣告它是純的——不碰 DOM、時鐘與亂數——而且每次呼叫都切成最長 1/240 秒的子步，所以相同輸入在任何幀率下都走出相同路徑（car.js:1-3）；判分則以固定 1/120 秒的子步進行，餘數帶到下一幀（engine.js:1-5）。車輛是以後軸為參考點的 kinematic bicycle model（car.js:247-256）。手排是它超出玩具等級的地方：離合器每個子步都當成 stick-slip 摩擦來解——算出讓引擎與離合器片等速所需的衝量，再用「接合度 × 260 Nm」夾住——配上扭力曲線、怠速控制器，以及低於 500 rpm 就熄火（car.js:300-332）。分享影片完全在裝置上產生：用多個鏡頭重拍回放、以 WebCodecs 編碼，再由手寫的 ftyp／moov／mdat muxer 寫出，剪接點對齊 120 BPM 的配樂（highlight.js:1、1133-1209）。全站沒有任何模型或貼圖檔；考場由 station 資料畫出，引擎聲用 Web Audio 合成。

stadia_controller遊戲設計 8.5/10

規則不是發明的，是謄寫的。rules.js:4-16 列出遊戲依循的兩張官方評分表——行政院公報的場考表（2026-03-31 版）與 2017 年的道路考驗表——底下的扣分目錄就逐條對著它們排。量不到的項目它會直說：左腳踩煞車、單手握方向盤都在表裡，但標著 sensed: false（rules.js:92、94）。政府沒公布的東西（例如場地尺寸）則在出現的每一處標上 // game setting，全案數百處，官方的數字與作者自己定的數字不會混在一起。難度接著用數據調，註解留著單據：v0.1.18 約 18,600 筆結果顯示倒車入庫只有 23% 通過（practice-hints.js:2-5）；照教練部落格尺寸做的曲線進退，開到這一站的玩家只有 2% 通過，第一次修改後是 3%，最後才改用車子自己打到底的圓來重畫彎道（stations/scurve.js:17-25）。搞笑層——考官的反應、吐槽——只讀不寫，不加任何扣分（fx.js:1-8）。

security後端與安全 6.5/10

表面積很小，客戶端處理得很仔細，伺服器端則不透明。同源端點只有三個：匿名事件 beacon、計數讀取，以及核發紀念駕照流水號的呼叫。隱私做得比這裡多數專案好：開了 Do Not Track 或 Global Privacy Control 就完全不送（stats.js:184），識別碼是兩個隨機值、分別每次開頁與每天更換，事件會經過白名單清洗，規則頁列出的傳送內容也與程式一致。回應 header 很嚴（script-src 'self'、object-src 'none'、HSTS），遊戲自己的 JavaScript 完全沒有 innerHTML 或 eval。拉低分數的有兩件事。成績在客戶端判定，而申請駕照的請求只帶 claim id 與排檔種類（license.js:176-182）——沒有任何東西把流水號綁到一場真的及格的考試。另外，請求不存在的路徑會回 HTTP 500 加上 Worker 的例外代碼，而不是 404。Worker 的原始碼、儲存方式與限流都看不到。

code程式品質 7.5/10

這一批裡分層最好的程式碼：模擬核心是純函式，engine 判分、scene 畫圖、controls 取樣輸入、app 外殼把它們接起來，依賴用注入的，所以模組可以在 Node 底下匯入。存檔讀取都經過修復式的清洗，每次寫入前還會重讀，舊分頁因此蓋不掉進度（records.js:15、75-89）。註解說明決策，並引用一套內部的計畫用語。債務很具體。有兩個檔案扛太多——scene.js 5,298 行、app.js 3,873 行。而全部 247 個 import 路徑到現在還寫著 ?v=0.1.0，遊戲卻已經到 0.1.29，新鮮度因此靠 must-revalidate 與 ETag 維持；程式用改成 namespace import、容忍缺少的 export 來繞開隨之而來的混版風險（stats-flow.js:6-8）。YaKyoLife 是手動維護 cache-bust token；這個專案則是不再維護它，改蓋一道防護。

experiment測試 4/10

沒有任何測試檔出貨，也觀察不到 CI，所以它不能被當成有測試的專案來評。分數之所以高於沒測試的專案，是因為成品的形狀看得出是被測試塑造出來的，而且註解點名得很精確：tests/fx.test.mjs 鎖住「搞笑層絕不改變判分」這條規則（fx.js:6），曲線進退與倒車入庫各有 station 測試，還描述了兩支輔助工具——一支開得完美的 autopilot，以及一個有反應延遲、用來掃描難度的「模擬學員」。有一則註解給出了結果：反應時間 1.5 秒時，舊的快速挑戰起點 15 次只停好 2 次，新起點是 11 次（garage-challenge.js:5-13）。架構與這套說法一致——純模組、注入的 fetch、storage 與時鐘。但外人讀不到、跑不了，也數不出其中任何一項。

verified完成度 9/10

上線第一週就做到產品等級。兩種駕照類別、自排與手排、有逐步提示的練習模式、可拖時間軸、慢放與換鏡頭的回看、三種尺寸的分享卡、挑戰連結、在裝置上產生的名場面影片，以及兩張紀念駕照。鍵盤與觸控兩套操作都完整，離合器可以換到畫面任一側，也尊重 reduced-motion。畫質分四階自動調整：中位數幀率持續低於 25 fps 就降一階，升階失敗就釘住，手機不會陷入反覆重編 shader（scene.js:1552-1563）。規則頁約兩萬字：扣分表、出處、「遊戲做不到的事」一節，以及資料蒐集的常見問題。遊戲內的更新紀錄用白話列出全部三十個版本。

emoji_objects原創性 7.5/10

駕駛模擬很常見；這一款做的事並不常見。題材是台灣自己的兩段式汽車考驗，規則引擎是逐條謄寫的官方評分表，程式還把政府沒給的每個數字都標出來。比起某個類型的又一款作品，它更接近對一套公共程序的忠實建模。框架是繼承來的，而且講明了：音訊模組寫著它是從同一位作者的機車路考遊戲 fork 來的，註解裡也反覆把「moto-parity」當成需求。新的題材，放在作者已經擁有的底盤上。

trending_up亮點

  • 用通過率調難度，數字就寫在註解裡——約 18,600 筆結果中倒車入庫 23% 通過，曲線進退先是 2%、再來 3%，之後才重畫（practice-hints.js:2-5、stations/scurve.js:17-25）
  • 在裝置上做出來的名場面影片——WebCodecs 的 H.264 加上手寫的 MP4 muxer，剪接對拍，什麼都不上傳（highlight.js:1、1133-1209）
  • 會熄火的 stick-slip 離合器——引擎慣量、隨踏板接合度縮放的摩擦容量、扭力曲線與怠速控制（car.js:300-332）
  • 把官方評分表當資料——公報出處寫在程式裡，偵測不到的項目標成 sensed: false，而不是悄悄拿掉（rules.js:4-16、92）
  • 尊重 DNT 與 GPC 的遙測——只要有其中一個訊號，beacon 就完全關閉，公開的常見問題也與程式實際送出的內容一致（stats.js:184）

trending_down弱點

  • 原始碼、測試與 Worker 全部不公開——沒有 repo、沒有授權；註解裡的每個通過率與每支測試都是作者自己的說法，無法重現
  • 成績由客戶端自報——申請駕照的請求只帶 claim id 與排檔種類，流水號並沒有綁定到一場及格的考試（license.js:176-182）
  • 不存在的路徑回 500——請求不存在的檔案會露出 Worker 的例外，而不是 404
  • 247 個凍結的 cache-bust token——版本已到 0.1.29，每個 import 還寫著 ?v=0.1.0，並加上 namespace import 來撐過混版（stats-flow.js:6-8）
  • 兩個過大的檔案——scene.js 5,298 行、app.js 3,873 行，其餘部分則分得很乾淨

三款沒有 repo 的遊戲

這是本報告中三個找不到公開 repo 的專案裡的第一個。先前八個都是 clone 下來連同完整歷史一起讀；這三個讀的是伺服器實際送到瀏覽器的東西，日期是 2026-11-17。

結果這樣就足以做到行號等級的閱讀，而且三款的原因相同：它們都沒有壓縮程式碼。這一款把 63 個 ES module 原樣出貨、沒有 build 步驟，所以設計理由、內部計畫編號，以及每次調整背後的通過率，全都在回應內容裡。

牆也就在這裡。git 歷史、commit 數、測試套件與伺服器端程式都不公開，所以這三頁的對應欄位寫的是「不明」而不是零，測試分數也設了上限：一支被點名卻讀不到的測試，只能算作流程存在的證據，不能算作驗證。

smart_toyAI 輔助開發跡象

出貨的檔案裡沒有點名任何工具。註解帶著的是一套「有計畫、分多個任務、由一個人核准」的開發用語：「plan convention」「Pinned interfaces」、任務編號、波次編號，以及有編號的裁決——fx.js:4 引用「ruling R6」，quips.js:2-3 說那些吐槽台詞「are drafts for the owner to approve (ruling R7)」。這讀起來像是在單一擁有者審核下的 agent 式開發，但這是從用詞做出的推論，沒有 commit 歷史可以證實。
