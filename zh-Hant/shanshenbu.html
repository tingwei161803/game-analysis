閃身步大亂鬥

把花鼓燈教學影片的迷因動作做成招式的瀏覽器格鬥遊戲：三招起手、三十多招可換、roguelite 闖關、全網踢館、Elo 排位——全部塞在一個 21,725 行的 HTML 裡，連線用 rollback netcode，電腦對手是自我對練訓練出來的神經網路。

七大面向

memory技術深度 8.5/10

三種在業餘瀏覽器遊戲裡很少見的技術，全部手寫在同一個檔案裡。Rollback netcode：兩端各跑同一套 60 Hz 模擬、只互傳一個按鍵 bitmask；模擬的那一步把 Math.random 換成有種子的 mulberry32（rbStep，index.html:14195），每格把浮點數量化（rbQ，:14187），每半秒對狀態做一次 FNV 雜湊（rbHash，:14143），對不上就由房主整份重傳；倒帶造成的位移只在繪製時平滑補上，不去動模擬值（:14097-14235）。傳輸分三層退守——兩條 WebRTC DataChannel，一條可靠、一條 maxRetransmits: 0（:14530），打不通走 Cloudflare TURN，再不行走 WebSocket 轉送。神經網路對手：純 JS 的 MLP 前向傳播，tanh 隱藏層、對 18 個動作做 softmax 抽樣（nnAct，:7982），而且餵給它的是 0.2 秒前的盤面，讓模型有人類的反應延遲（:7906）；檢視的兩個模型檔分別是 58-128-128-18 與 359-256-256-18。程序化動畫：每個角色都是由 16 個關節角度算出來的骨架（skeleton，:3405），姿勢之間用 Catmull-Rom 補間（splinePose，:3293），關鍵格是從原片逐格抓出來的。

stadia_controller遊戲設計 8/10

招式是資料而不是程式：每招都是 {cd, dur, keys, ev}，其中 ev 是一條時間軸，排著打擊、抓技、飛行道具、防禦窗（無敵、格擋、反射、反擊、精準防禦）、增益、跳躍與俯衝（MOVES，:3900）。於是三十招的招式池擴充很便宜，下架也很便宜——有十三招被關掉但資料留在表裡（MOVE_OFF，:3999）。格鬥本體之外還有逐關成長加七項傳承樹的 roguelite 闖關、踢館，以及 Elo 排位：前十場 K=40、之後 24（rkDelta，:19954）。少見的是平衡註解會引用實跑結果：調整雜兵上限的理由是各打 10 局、平均死在第 25.0 關變成 26.0 關（:15430），而「亂按、走神都弱不了多少，真正有效的是限制出招頻率」（:19347）這種結論只有量過才得得出來。同一批註解也坦白有些數字就是寫的人定的。

security後端與安全 6/10

有真的後端——Workers、Durable Object、D1、TURN、Google 登入——但只能從外面評，因為 worker.js 從來不會送到瀏覽器。看得到的部分好壞參半。好的一面：作者對自己的程式做過資安審查，還把發現留在註解裡——#mv= 搬家匯入原本可以覆寫任意 ssb_* 鍵，搭配 innerHTML 就能拿走後台金鑰，現在改成白名單加 referrer 檢查（:32-44）；存檔戰績欄位沒驗型別造成的儲存型 XSS，由 profClean 補上（:15474-15493）。伺服器送來的名字都有跳脫。存檔碼用 crypto.getRandomValues 產生，並與公開的 UID 分開。弱的一面：闖關成績是客戶端自報的 {cleared, kills, dur}（rgSend，:21013），伺服器只檢查時間合不合理，另外有十幾張常數表要靠人工與伺服器保持一致。

code程式品質 4.5/10

兩件相反的事同時成立。註解是本次體檢最好的「為什麼」型文件：幾乎每個修正都附日期、促成它的數字，以及還沒解決的部分——roundRect 的 polyfill 註明 11-10 到 11-12 共 4,565 次錯誤回報（:2915）。結構則是最差的：18,841 行 JavaScript 全在一個全域作用域、881 個頂層函式、920 行超過 300 字元、最長的一行 9,475 字元。這個檔案自己記下了代價：有一行程式「黏在上一行註解尾巴、從來沒跑過」，於是 AI 的輸入變成 NaN、動作卡死（:5146）。2.66 MB 的檔案同時也是整個首次載入。

experiment測試 3/10

出貨物裡沒有任何可測的東西。註解提到私有工具——重現連線不同步的 tools/rb_netcheck.cjs（「1 場不同步 88 次、整份重傳 45 次；改完 0 次」，:7763）、tools/guard_check.mjs 與 tools/ai/sim.js——但外人讀不到、也無法重跑。在正式環境裡代替測試的是遙測：每次造訪最多三種不同的錯誤訊息會隨心跳上報，另外有一套 A/B 框架，目前只跑著一個 A/A 檢查。這是監控而不是驗證，分數也是照這個標準給的。

verified完成度 9/10

以功能數量計，是本次體檢最完整的產品：馬上玩、新手教學、本地雙人、附邀請連結與 QR code 的線上房間、觀戰、有 ban/pick 的排位、踢館、含每日挑戰的闖關、四人合作與練習場；外加商城、每日任務、成就、雲端存檔、PWA、Android 殼，以及九個靜態頁（含隱私權政策與更新日誌）。營運細節特別突出：sw.js 主要就是為了處理「停在舊版沒重新整理的分頁」，只在不是對局中的時候透過 service worker 重新載入，它的註解記著一小時內在線約 1,956 台裝置、其中至少 170 台是舊頁（sw.js:10-31）。四個環境以 hostname 區分，除錯開關在正式站無效。

emoji_objects原創性 8/10

不是既有遊戲的換皮。題材是 2026 年的網路迷因——一位民俗舞蹈老師喊著招式名——機制也是從題材長出來的：喊出來的那三招就是三個起手招式，動畫的關鍵格取自原片。周邊系統（闖關階梯、轉蛋造型、Elo）是類型標配，但在四週內把它們組裝在一款有 rollback、有訓練過的 bot 的格鬥遊戲周圍，並不是。扣分在於未說明依據就拿來用的部分：語音是原片的人聲（:2951），幾個角色則以認得出來的公眾人物為原型。

trending_up亮點

  • 瀏覽器裡的 rollback netcode——決定性的 60 Hz 模擬、交換按鍵 bitmask、換上有種子的 PRNG、浮點量化、FNV 狀態雜湊，以及整份重傳的後備方案（index.html:14097-14235）
  • 「爆 ping 只害到自己」——只有當自己到伺服器的 ping 證明網路正常時，才把對手晚到的按鍵定案為沒按（:14101、rbCommitTo :14231）
  • 有反應延遲、自我對練訓練出來的對手——手寫的 MLP 前向傳播，看到的是 0.2 秒前的盤面；低段位靠限制出招頻率來變弱，而不是靠亂按（:7906、:7982、:19347）
  • 不用任何美術資產的骨架動畫——16 個角度的姿勢向量加 Catmull-Rom 補間，關鍵格取自原片（:3293、:3405）
  • 用 service worker 淘汰舊分頁——瀏覽器唯一會自動更新的腳本被拿來重新載入舊頁，但絕不在對局中動手（sw.js:10-66）

trending_down弱點

  • 排位賽的電腦以玩家的樣子出現——十秒內配不到真人就換成電腦，而且依程式註解是「電腦裝成真人（名字、造型、算分都一樣）」（:19341），名字產生器還特意調過以免露餡（:19373）；查過的常見問題、玩法教學與隱私權頁都沒有提到這件事
  • 一個 2.66 MB 的檔案、一個全域作用域——881 個頂層函式、最長一行 9,475 字元；這種排版已經造成過真的 bug：程式黏在註解後面、從來沒被執行（:5146）
  • 原始碼不公開、沒有授權——註解引用的模擬、訓練與連線檢查工具全在私有的目錄裡，所以引用的數字一個都無法重現
  • 語音與肖像的使用依據沒有說明——語音是原片的人聲（:2951），幾個角色以認得出來的公眾人物為原型，而網站同時掛著廣告；沒有找到授權或許可聲明。這是風險提示，不是侵權認定
  • 客戶端與伺服器的常數靠人工同步——有一則註解自承伺服器「還沒有這些場地（存檔會被 saveGuard 拿掉）」（:10859）

沒有 repo，但網頁本身就是原始碼

找不到這款遊戲的 repo，GitHub 上一份第三方鏡像也明講不含伺服器端。但它卻是本次體檢最讀得懂的專案之一，因為出貨的 index.html 沒有壓縮：21,725 行、註解全部保留、用中文寫、日期精確到天。

這些註解的功能等同一份事故紀錄。它們記下什麼壞了、壞了幾次、試過什麼、還有什麼沒解決：一個 polyfill 附它的錯誤次數、一個連線修正附修正前後的不同步次數、一條 service worker 規則附它是為了多少台舊裝置而寫的。它們也記下作者對自己程式做出的資安發現——這種筆記多數專案就算寫了也不會公開。

這種讀法的極限在於：註解是證詞，不是證據。模擬實跑、訓練流程、伺服器端的存檔防護都有描述，卻一個也無法檢視。這裡的分數獎勵的是出貨檔案展示出來的東西，並對它只是轉述的部分打折。

smart_toyAI 輔助開發跡象

程式裡點名了 AI 審查：有三則日期為 11-11 的註解標著「（Opus 審查）」，就寫在它促成的修正旁邊（:14722、:15066、:15493），其他註解還提到資安稽核實跑、總審查清單與有編號的找 bug 總表。註解也以幾個簡短的代號署名，包括「owner」與「junior」；這些是真人還是 agent 的角色，從成品無法判斷。沒有 commit 歷史，AI 寫的程式碼占多少也不得而知。對手則是另一回事：它們是自我對練訓練出來的小型神經網路，那是遊戲裡面的機器學習，不是開發過程中的 AI 輔助。

總評

本次體檢技術野心最大的一款——rollback 連線、訓練出來的對手、程序化動畫，大約四週內做成有排位、有 App 殼的營運中產品，註解坦白得少見。拖住它的是已經讓它付出 bug 代價的單檔結構、外人無從查核的工具與伺服器端程式，以及一個用沒有告知玩家的電腦來填補空位的排位賽。
