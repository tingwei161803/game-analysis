麻糬派對

一個大廳底下五款四人合作派對遊戲，一人一支手機：在餐車前面鋪路、撐過 78 個三秒小遊戲、夜闖鬧鬼校舍、辦森林宴會、搬易碎家具。瀏覽器只送輸入，遊戲由 Rust 伺服器執行；單人局則把同一份模擬編成 WebAssembly 在手機上跑，伺服器重播操作紀錄、結果相符才發獎勵。

七大面向

memory技術深度 8.5/10

五款遊戲有四款是架在權威伺服器上的薄客戶端：web/main.js:1 開頭的註解寫明客戶端只送輸入、畫伺服器送來的狀態，輸入迴圈在輸入改變或每 0.2 秒送一則 {t:'in',x,y,b}（web/main.js:845-846）。註解描述伺服器是 Rust crate，取代了更早的 Go 版本（web/hints.js:4）。最突出的是鋪路餐車的單人局：同一份模擬以 WebAssembly 出貨，包成一個長得像 WebSocket 的物件，畫面程式完全不用改，每 50 ms 前進一步；結算時客戶端上傳單子、版本、開局參數、操作紀錄與宣稱的結果，伺服器重播一遍才發獎勵（web/localroad.js:1-6、web/localroad.js:153）。房間流量走自製協定：整條連線共用一個 raw deflate 串流，加上客戶端補幀——靜止畫面依每個數字的變化率補出一樣的幀，伺服器跳過一幀時插入中間幀（web/meta/wsz.js:1-12、web/meta/wsz.js:42-68）。重連時是把卡住的連線換掉而不是兩條並行，因為 Chrome 對同一個 host 一次只讓一條握手（web/meta/api.js:98-113）。每幀的物件配置由程式產生器提到常數區（web/render.js:25、web/render.js:46）。限制：完全沒有打包——首頁的靜態 import 圖是 92 個檔案、Brotli 壓縮前約 2.8 MB，全部以 cache-control: no-cache 送出——而伺服器與 .wasm 都沒有讀到。

stadia_controller遊戲設計 8/10

每一款都拿一個熟悉的合作玩法當底，再加一條把失敗變成笑點、而不是變成牆的規則。鋪路餐車翻車後開「甩鍋法庭」：播放回放、大家投票選戰犯，輸的人戴鴨子頭示眾一段路（web/i18n.js:205、web/i18n.js:521）；結算畫面是一段從這場事件紀錄套句型組出來的新聞稿（web/i18n.js:645-646）。夜遊鬼校舍裡被抓到的人不會出局，而是變成搗蛋鬼，對隊友關燈、關門（web/ghost/i18n.js:8-9）。宴會大廚明寫沒有失敗、只有更熱鬧（web/banquet/i18n.js:7）。三秒亂鬥列了五個主題共 78 個小遊戲，其中 14 個把同一個畫面拆到四支手機、10 個用傾斜、搖晃或麥克風並備有觸控版（web/micro/games/index.js:4-27）；執行器在掉幀時以 1/60 秒切小步，讓點擊對上它真正發生那一刻的畫面（web/micro/play.js:39-43）。無障礙是設計的一部分：Okabe–Ito 色盲配色、字體縮放、減少動態（web/meta/settings.js:4-6），還有照樣算星星與解鎖的輕鬆模式（web/i18n.js:14）。限制：平衡數值放在伺服器，客戶端看不到量測調校的痕跡，而這次體檢是讀程式，不是實際遊玩。

security後端與安全 7.5/10

本次體檢伺服器面積最大的一款——客戶端點名了 111 個不同的 /api/ 路徑，涵蓋登入、好友、聊天、檢舉、停權與申訴、信箱、購買與推播——但一行都讀不到，所以分數建立在部署姿態，以及客戶端被允許做什麼。標頭很嚴：CSP 是 default-src 'self'，第三方 script 只放行 Google 登入（樣式則允許 'unsafe-inline'），HSTS 一年，nosniff，Permissions-Policy 只留麥克風與動作感應器給本站。不存在的路徑回純文字 404；沒有 robots.txt。登入 token 走 Authorization 標頭與 WebSocket 子協定，不放網址（web/meta/api.js:39、web/meta/api.js:66-69），?pid= 測試參數只在本機位址有效（web/meta/api.js:15-18）。隨機的裝置編號同時存在 localStorage、IndexedDB 與 400 天的 cookie，三處互相補回，用於限制訪客帳號與執行停權（web/meta/api.js:232-234）；隱私權政策有揭露。沒有找到任何分析或追蹤程式，與 privacy.html:60 相符。衛生筆記：小遊戲結果依設計由客戶端回報（web/micro/main.js:2），/api/info 會回傳容器映像的名稱，而政策說 Cloudflare 只提供 DNS（privacy.html:74），index.html:8-11 卻記著圖示與預覽圖在 2026-11-03 搬到了 Cloudflare Pages。

code程式品質 7/10

註解是本次體檢最好的文件：講原因、講裝置，還常常附量測。web/meta/api.js:98-107 用一支指名的手機在 Android 15、4G 上的實測解釋重連設計，連 TCP 的 SYN 以 1 → 3 → 7 秒重送都寫進去；web/audio.js:6-11 記著為什麼 AAC 檔要用 .mp4 副檔名。結構是真的 ES module，一款遊戲一個資料夾，加上共用的 meta/，並交叉引用一份 CONTRACT 文件的 15 個不同章節。失敗有被圍住：某個小遊戲檔載入失敗只會少那一個遊戲（web/micro/games/index.js:29），畫面出錯會被接住並還原 canvas 狀態（web/micro/play.js:89）。債務在結構上。web/main.js:431-600 的 onSnap 是一條 170 行、依特效代號分支的條件鏈；有 1,045 行超過 250 個字元；共有 192 個不同的 window.__* 全域變數，許多是留在正式環境裡的測試掛鉤（web/main.js:82-121）；正式的角色繪製模組是從名為 demos/ 的資料夾送出的，第一個檔案開頭還是提案動畫舞台的說明（demos/stage.js:1-13）；語言偵測則在每款遊戲的 i18n.js 裡各抄一份。出貨的檔案同時也是配置提升產生器的輸出，會留下像 web/micro/games/fly.js:176 這樣的痕跡：從第 41 行定義的物件讀 _K20.rot，而那個物件沒有這個欄位。

experiment測試 4/10

客戶端到處都點名了測試，但一支都沒有出貨，所以這裡落在二手證據的上限。名字很具體：cargo test -p meta --test cosaudit 作為外觀的上線閘門（web/meta/roomfx.js:6）、server-rs/crates/meta/tests/retier.rs::rarityfx_tables 把客戶端的表跟目錄逐件比對（demos/rarityfx.js:201）、WebAssembly 對伺服器的對拍入口（web/roadsim.js:1、web/roadsim.js:42），以及驅動瀏覽器的工具 cdp.mjs 與 playtest.mjs（web/render.js:1724、web/meta/wsz.js:176）。程式看得出是為了被驅動而寫的：「畫面測試」一詞出現 75 次，window.__state 交出整份遊戲狀態的唯讀深拷貝（web/main.js:82-121），每個小遊戲都實作 auto(want)，讓 bot 或測試工具可以指定要過關或失敗（web/micro/play.js:6），連 service worker 都有一個讓無頭 Chrome 點通知的掛鉤（sw.js:56-57）。單人局核對這條路本身也是在正式環境裡跑的決定性檢查：手機與伺服器對回放的結果不一致，就不發獎勵（web/localroad.js:164）。從外面看不出來的是測試涵蓋多少、有沒有通過，以及部署前有沒有任何把關。

verified完成度 9/10

這是一個營運中的服務，遊戲周邊的整套機制都在。一個大廳通往五款遊戲，可以開派對房、快速配對、邀請好友；空位由 bot 補上。周邊有訪客帳號與 Google、LINE、Apple 綁定、好友與聊天（字詞過濾與伺服器同一套，web/meta/chat-filter.js:1-2）、檢舉、停權與遊戲內申訴、信箱、任務、季票、附公開機率表與保底計數的扭蛋、兌換碼、網頁推播，以及一整個用程式畫出來的外觀衣櫃。全部都有中英雙語，包含隱私權政策、服務條款與客服頁。註解描述了 iOS 的 Capacitor App 與 Android 的 TWA，購買在那裡進行；網頁版看得到價格但不收款（web/meta/pay.js:4-8）。內容量很足：78 個小遊戲、鬼校舍 7 關、宴會 12 關、搬家 15 關（web/ghost/i18n.js:254、web/banquet/i18n.js:202、web/moving/i18n.js:287）。缺口很小，而且多半是自己寫明的：Boss 戰音樂還沒產出、先退回別首曲子（web/audio.js:15、web/audio.js:22），PWA 圖示標著暫定版（index.html:24），service worker 只負責推播、不做離線快取（sw.js:1-2），另有 18 個小遊戲已經出貨，但伺服器要開了開關才會抽到（web/micro/games/index.js:18）。

emoji_objects原創性 7/10

五個框架都是既有的合作類型——在移動的車輛前面鋪路、連發的小遊戲闖關、共用廚房、搬家具、逃出鬧鬼的建築——而網站沒有製作名單或靈感來源頁；程式裡唯一點名的參照，是一行把扭蛋轉輪稱為 CS:GO 式的註解（web/meta/gacha.js:1）。屬於這個專案自己的，是把框架串起來、填進去的東西。同一隻麻糬仔完全由壓扁、傾斜、拉扯這類參數畫出來（demos/mochi.js:1-12），穿著同一個衣櫃走過五款遊戲。甩鍋法庭把合作局最慘的一刻變成一場看回放證據的投票，連罪證台詞都依生物各寫一句（web/i18n.js:245）。結算是用合成的麻糬語唸出來的新聞稿，不是文字轉語音（web/main.js:74）。把一個畫面拆到四支手機的小遊戲，是這個類型單一螢幕的前輩做不到的形式。而扭蛋的註解記下了一項節制：轉輪照公開機率填格子，不把稀有款擺在結果旁邊（web/meta/gacha.js:1）。這個合輯的形狀是借來的；語氣與串接的系統是它自己的。

trending_up亮點

  • 可核對的本機模擬——鋪路餐車單人局把 Rust 模擬編成 WebAssembly 在手機上跑，外面包成長得像 WebSocket 的物件，結算時上傳操作紀錄，伺服器重播相符才發獎勵（web/localroad.js:1-6）。
  • 手寫的省流量協定——整條連線共用一個 deflate 串流，靜止畫面由客戶端依每個數字的變化率補幀，分頁從背景回來時用一來一回的對時追上（web/meta/wsz.js:1-12）。
  • 一個執行器帶 78 個小遊戲——每個都是帶 setup、update、draw、result、auto 的小物件，用 Object.create 開實例，同一個模組可以同時開很多份（web/micro/play.js:1-6、web/micro/games/index.js:1）。
  • 帶著實測資料的註解——重連邏輯引用一支指名的手機、Android 15 與 4G，並解釋為什麼是換掉卡住的連線而不是兩條並行（web/meta/api.js:98-107）。
  • 照程式寫的隱私權政策——HTML 註解寫明 2026-10-05 依程式實際行為重寫（privacy.html:16-19），「沒有第三方分析」的說法與 CSP 以及對客戶端的搜尋結果都對得上。
  • 無障礙是設定，不是補丁——Okabe–Ito 配色的色盲玩家色、字體縮放、減少動態與震動開關，五款遊戲都讀同一份（web/meta/settings.js:4-6）。

trending_down弱點

  • 伺服器程式與測試都讀不到——關於權威、雜湊與核對的每一項說法，依據的都是客戶端註解與觀察到的行為；測試檔有被點名（demos/rarityfx.js:201、web/meta/roomfx.js:6），但沒有出貨。
  • 沒有打包的交付——首頁的靜態 import 圖是 92 個檔案、Brotli 壓縮前約 2.8 MB，在 cache-control: no-cache 之下每次造訪都要逐一重新驗證，檔名也沒有雜湊。
  • 測試掛鉤留在正式環境——192 個不同的 window.__* 全域變數、window.__state 的整份狀態輸出（web/main.js:82-121），以及把畫面狀態開放寫入的 ?hook=1（web/main.js:742）。
  • 小遊戲由客戶端判定——三秒亂鬥在手機上決定過關與否，再回報 {t:'res', ok, ms}（web/micro/main.js:2、web/micro/main.js:840）；檔頭註解講得很明白，但這是唯一一款伺服器照客戶端說法收下的遊戲。
  • 原型時期的命名還在——正式的美術模組從 demos/ 送出，web/main.js:1 仍自稱原型客戶端，/api/info 回報的映像名稱是 mochi-party-proto。
  • 有一行政策被頁面超車——隱私權政策說 Cloudflare 只提供 DNS（privacy.html:74），index.html:8-11 卻記著圖示與預覽圖在 2026-11-03 搬到了 Cloudflare Pages。
  • 函式長、行也長——onSnap 是 170 行依特效代號分支的條件式（web/main.js:431-600），整個客戶端有 1,045 行超過 250 個字元。
  • 抽樣閱讀——這次體檢在 79,354 行客戶端程式中完整讀過的約 2,800 行（大廳、本機模擬、連線與一支小遊戲），其餘是抽樣；這裡的論斷描述的是那些檔案，不該延伸到整個程式庫

手機跑遊戲，伺服器重播一遍

多數伺服器權威的遊戲，為了這份權威要替每個房間養一個活著的行程。鋪路餐車的單人局換了做法。客戶端先跟伺服器拿一張帶 seed 與版本的單子，載入 road.wasm，確認版本一致，然後每 50 ms 在本機前進一步。web/localroad.js:3 說它產生的訊息跟伺服器房間逐字相同，所以畫面程式不用改：LocalSocket 像真的連線一樣提供 send、onmessage 與 readyState。一局結束時，手機上傳單子、開局參數、操作紀錄與它宣稱的結果；伺服器重算一遍，兩邊一致才發獎勵。

失敗的路徑是想過的，不是假設不會發生。不支援 WebAssembly、下載失敗或版本不對，都會安靜地退回一般的伺服器房間（web/localroad.js:74-87）。核對服務忙線時客戶端重試八次，再不行就把結果留在裝置上最多 70 分鐘，下一局開始前補送（web/localroad.js:13-16、web/localroad.js:172-176）。index.html:8-11 的一段註解給了這件事可能的動機：預覽圖之所以搬離遊戲主機，是因為爬蟲一直把沒人玩、已經關機的伺服器叫醒。

但書跟本次體檢其他地方一樣：核對程式在伺服器上，沒有讀到。客戶端呈現的是這份契約的形狀——單子、版本檢查、決定性的步進函式、操作紀錄——而這個形狀與「重播核對確實存在」是一致的。

smart_toyAI 輔助開發跡象

成品本身沒有任何關於開發過程使用 AI 的說明：沒有製作名單、沒有 repository，因此也沒有 commit 署名，註解裡不曾出現任何工具名稱。僅有的兩處提到 AI，講的是產品而不是製作：隱私權政策說聊天過濾用的是規則與字詞表，「不使用 AI」（privacy.html:34），web/meta/chat-filter.js:2 則寫明過濾不接 LLM。以下純屬推論：註解提到標為 A、B、C、D、M、X 的平行工作線、名稱像 desk/bg-keep2 的工作區、編號的工作項目，以及一位回報問題並拍板產品決定、名叫 Ray 的人（web/roomgate.js:1）。這描述的是由一個人主導、多線並行的有組織工作流；成品沒有說這些線是人還是工具。

總評

這一批裡完成度最高、工程最深的一款，也是實際讀得到的工程比例最低的一款。光是客戶端就有約 7.9 萬行，橫跨五款遊戲與完整的帳號、社交與商店層；連線上的決定都用真機量測來解釋，還有一套任何規模的專案都少有人嘗試的可核對本機模擬。分數停在證據停下來的地方：Rust 伺服器、WebAssembly 模組與所有測試都在視線之外，而看得到的部分帶著快速成長的痕跡——沒有打包的交付、留在正式環境的測試掛鉤，以及仍以原型命名的資料夾。
