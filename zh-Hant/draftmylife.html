七大面向

memory技術深度 8/10

技術上的核心想法，是把程式與模型的分工劃清，並用程式碼強制執行。瀏覽器負責推進結構化的行事曆、擲出每一個結果，再送出一份 JSON 資料；請求裡只帶 messages，註解寫明模型、工具與 system prompt 都由 Worker 決定，前端就算送了也會被忽略（index.html:17596-17597、10415-10417）。回覆必須是強制的工具呼叫，另有一道驗證專門擋下模型把偽 XML 寫進欄位的情況（index.html:17696-17708）。回來的內容再分成三類：重新產生（整回合最多一次）、由程式直接修、或只記錄（index.html:11123、11441）。模型回報的數字會被截斷——STAT_DELTA_LIMITS 與意外之財上限之所以存在，是因為玩家可以用文字說服模型讓自己中樂透（index.html:1073-1101）。外圍還有含農曆節日的真實日曆、依年齡帶分配的回合預算（index.html:7390-7399）、讓重試不會重複扣點的每回合 nonce，以及每次讀檔都會執行的約二十道遷移與補值步驟（index.html:5754-5776）。奇幻篇則是另一顆由 37 個模組組成的引擎，亂數可注入種子（fantasy/engine/rng.js:2-12），連線管道以參數傳入。限制在於：現代篇是一支 26,654 行的行內 script，只有一個全域 state；而放著提示詞與錢包的 Worker 讀不到。

stadia_controller遊戲設計 8/10

設計原則在註解裡反覆出現：模型負責敘事，程式負責決定。死亡是每年一次的擲骰，機率是年齡表乘上健康倍率，而且第一次命中只會埋下前兆，第二次才進入結局（index.html:10484-10507）。求職錄取是一道攤開的加總——基礎 35，加上才識、人脈、科系對口、年齡扣分，限制在 5–90%——同一份明細物件既拿來擲骰，也拿來在畫面上說明（index.html:4129-4152）。才識的成長來自模型挑的事件標籤，再由程式查表擲值，里程碑在每個人生階段有上限（index.html:3106-3130）。每回合由一段自由輸入或選項的「回應」搭配一個「重心」組成，成長由重心另外結算，所以文筆好不能取代讀書。「閉眼過日子」讓角色在玩家離線時依性格加權的傾向標籤自己過，而且玩家不在時不會判定死亡或重大疾病（index.html:18557-18600）。奇幻篇的序幕多了一條由驗證器把關的世界規則——一個「被忘」的人，只有玩家叫得出名字（fantasy/engine/ai.js:105-129）。限制是程式自己寫明的：有 307 行帶著 【測試參數】 標記；檔頭註解說實測一段完整人生約 2,000–2,100 回合，與一到兩小時的目標矛盾（index.html:1044）；而且每一回合都要花一張購買或配給的「稿紙」。生成文字的品質無法從出貨物判斷。

security後端與安全 7.5/10

這是本次體檢中唯一背後有真正服務的人生模擬：一支位於 life-game.smile80275.workers.dev 的 Cloudflare Worker，負責信箱驗證碼帳號、共用錢包、雲端存檔、AI 代理與藍新金流結帳。看得到的部分做得很小心。頁面送出的是強制執行的 Content-Security-Policy，connect-src 只列自己與那支 Worker，form-action 只列金流閘道，並設了 frame-ancestors 'none'。結帳頁自己另有一份閘道網址白名單（buy，片段 var FORM_LIVE = [）。復原金鑰已從 GET 網址改放到標頭，並留有日期註記（index.html:1059-1060）。奇幻篇的統計事件先過一份欄位白名單，自由文字會被丟掉（fantasy/analytics.js:39-56），而隱私權政策（版本 2.1）列出的正是這些欄位、交給 AI 服務商處理這件事，以及管理員可查看存檔。註解裡留著團隊自己做資安掃描的編號發現（資安H4、M6、M7、L3）。限制在於：因為遊戲是行內 script，CSP 允許 'unsafe-inline'；登入憑證與復原金鑰放在 localStorage；任何不存在的路徑（包含 robots.txt）都以 200 回傳 2.2 MB 的遊戲頁；頁面帶著 access-control-allow-origin: *；而真正執行餘額、頻率限制與提示詞的 Worker 程式讀不到，這些控管只能從註解得知。

code程式品質 6/10

同一個網域上放著兩套習慣相反的程式。現代篇是單一支 27,704 行的 index.html：一段行內 script 裡約 1,800 個函式、一個全域 let state（index.html:5345）、260 行超過 300 個字元的程式，以及 119 個空的 catch(e){}。較晚寫的奇幻篇則是 37 個 ES 模組，沒有一支超過 1,142 行，儲存、連線、亂數與 AI 呼叫全部以參數注入（fantasy/slots.js:10、fantasy/backend.js:129、fantasy/engine/turn.js:133）——是為了能在 Node 底下執行而寫的形狀。撐住那個大檔的是註解。幾乎每一段都標著設計文件的章節、日期，以及 【定案】、【測試參數】 這類狀態標記；修 bug 時會寫出是哪一次試玩發現的，例如手足名字與性別不符的問題追到一份標了日期的 PDF（index.html:6296）。AI 寫的文字在進 innerHTML 之前都經過跳脫（index.html:24359-24361、24415-24418）。也看得到殘留：前端有一個 MODEL 常數，而後來的註解說伺服器會忽略它（index.html:1068）；有個函式參數一進來就被覆寫（index.html:5779-5780）；還有一處名稱衝突是靠註解提醒、不是靠作用域避開（index.html:18600）。檔案都沒有壓縮，所以以上都是讀到的事實；Worker 與建置腳本則看不到。

experiment測試 4/10

站台沒有送出任何測試檔，但出貨的程式提到測試套件的次數與具體程度，是本次體檢所有不公開原始碼的專案中最高的。註解點名了 tests/test-54-version.mjs，說它會檢查頁面版本、更新紀錄與 Worker 版本是否對上（index.html:16351）；tests/test-80，說它會比對法律頁面與常數（index.html:5534）；tests/test-84-turn-flow.mjs，說它會掃描反悔快照清單漏掉的狀態欄位（index.html:18077）；以及 tests/test-307，說它會檢查奇幻篇頁面裡三處版本號（fantasy/index.html:16）。從編號看來測試檔有數百支，這一點是推論。另有一份 150 句人工標註的 fixture，附上召回率與誤報率（index.html:9513）；註解也提到 60 局模擬，以及為死亡機率表做的 20 萬樣本網格搜尋（index.html:2457、10483）。奇幻篇的引擎明顯是為測試而寫：亂數產生器第一行就這麼說（fantasy/engine/rng.js:1），還有假 AI、假連線管道，現代篇也附了一個離線旁白（index.html:17866）。抓取當天，Worker 的 /version 與頁面的 APP_VERSION 一致。但這些測試都讀不到、也跑不了，看不到 CI，請求 tests/ 得到的是遊戲頁。依本站規則，這種情況最高 4 分，而它拿得到這個上限。

verified完成度 8.5/10

這是一個營運中的商業服務，不是展示品。現代篇從高中玩到死亡，有結局、轉世或傳承到下一世、把一個人生階段寫成小說章節的「人生之書」、放置模式、三格存檔加雲端備份，以及語音輸入。周邊有信箱帳號、附明細頁的錢包、列出單次稿紙包、訂閱與自選金額的收費說明、候補名單、推薦碼與兌換碼、遊戲內回饋管道，以及附投票的「主編的信」。另有服務條款（版本 2.0）、隱私權政策（2.1）、退款規則、每一頁法律文件都有的分級標示、自帶版本號的同意頁（index.html:5528-5548）、十三節的玩法說明，以及從 2026-09-29 到 2026-11-17 共 178 則寫給玩家看的更新紀錄，而且訂了不暴雷的寫法規則（index.html:16349-16356）。沒做完的地方也很清楚。奇幻篇只有序幕：PROLOGUE_ONLY = true 讓它停在「第一幕即將推出」（fantasy/engine/data.js:387），雖然引擎裡已經放著後面幾幕的檔案。開發日誌頁寫著日誌還在整理。沒有 robots.txt 與 sitemap，介面只有中文，遊戲停用了雙指縮放，而主頁是一份 2.2 MB 的文件，另外還要載入一套放在自己站上的 973 KB 字型。

emoji_objects原創性 8/10

由語言模型敘事的人生模擬已經是既有的想法；這個專案自己的東西，是它讓模型做的事有多少。模型拿到的是一份每段關係都已算好分數的名冊、一個不能超出的日期範圍，以及這回合必須發生的事項清單；它交回正文與幾個列舉式標籤，記帳由程式來做。包裝也一致、而且是它自己的：玩家是「撰稿人」，回合要花「稿紙」，經營者以「編輯部」自稱，更新說明以「主編的信」的形式送達。奇幻篇有原創的前提——一個現代成年人在十五歲的身體裡醒來，那個世界裡有些人被所有人遺忘，只有玩家記得——以及一份點名禁用特定套句的文風規範（fantasy/engine/prompt.js，片段 不用這些套句）。和本站已收錄的兩款台灣文字人生模擬相比，機制在本質上不同：yakyulife 與 cheerlife 是只在前端執行、文字由人寫好、沒有伺服器的遊戲，這一款則是把每一回合送到帳號與錢包後面的付費模型。三者都由程式擲出結果、都用繁體中文書寫；出貨物裡沒有任何地方說它們之間有關聯。奇幻篇的開局擲骰沿用了現代篇的步驟，註解直接寫明這一點（fantasy/engine/roll.js:1）。

trending_up亮點

  • 模型寫字，程式決定——請求只帶 messages，模型、工具與 system prompt 由伺服器固定；死亡、疾病、錄取與考試結果在呼叫模型之前就由瀏覽器擲好（index.html:17596-17599、10497-10507）
  • 每一則回覆都過三類檢查——重新產生（整回合最多一次）、程式直接修、或只記錄，每一項都有短代碼，並當作統計回傳（index.html:11123、11441-11520）
  • 顯示的機率就是擲骰的機率——求職錄取的明細物件，加總拿去擲骰，同一份清單也印給玩家看（index.html:4129-4160）
  • 防止用文字說服模型——單回合意外之財與數值變動上限，起因是玩家可以說服模型自己中了樂透（index.html:1073-1101）
  • 強制執行的 CSP，以及與程式相符的隱私權政策——connect-src 只限本站與一支 Worker，統計事件的白名單會丟掉自由文字（fantasy/analytics.js:39-56）
  • 用相反方式寫的第二顆引擎——37 個小型 ES 模組，亂數有種子，儲存、連線與 AI 呼叫都以注入方式傳入（fantasy/engine/rng.js:2-12、fantasy/engine/turn.js:126-148）

trending_down弱點

  • 單一支 27,704 行的 HTML——一段行內 script 裡約 1,800 個函式圍著一個全域 state，另有 119 個空的 catch(e){}（index.html:5345）
  • 測試只以被提到的形式存在——註解點名了四支測試檔，但一支都沒有送出，也看不到 CI（index.html:16351、18077）
  • 平衡自己標明尚未定案——307 行帶著 【測試參數】 標記，檔頭註解記錄一段完整人生約 2,000–2,100 回合，與一到兩小時的目標矛盾（index.html:1044）
  • 線上的奇幻篇序幕是事先寫好的文字——正式網域會忽略 ?ai 參數，所以 callAI 是 null，每回合跑的是寫好的旁白，而沒買過稿紙的帳號每回合仍扣一張（fantasy/pageParams.js:5-6、fantasy/ui.js:37、835、fantasy/prologueCharge.js:6-13）
  • 任何不存在的路徑都回傳遊戲本體——robots.txt、sitemap.xml 與任何打錯的網址都以 200 回應 2.2 MB 的頁面，並帶著 access-control-allow-origin: *
  • 機密放在 localStorage，CSP 帶著 'unsafe-inline'——復原金鑰與 90 天的登入憑證存在瀏覽器裡，金鑰隨每回合的請求內容送出（index.html:17600）；行內 script 的做法讓政策無法禁止行內程式
  • 伺服器無法受檢——提示詞、錢包、頻率限制與金流回呼都在 Worker 裡，這次只能透過 worker/prompt.js、worker/ap.js 這類註解得知它的存在

替說書人請了一位裁判

多數 AI 故事遊戲把筆和骰子一起交給模型。這一款把骰子收走，然後檢查字跡。classifyTurnOutput 讀過每一則回覆，把發現的問題歸到三個標題底下，定義寫在同一則註解裡：第 1 類重新產生，整回合最多一次；第 2 類由程式直接修，不再問模型；第 3 類只記錄（index.html:11123）。第 1 類包括新場景的日期落在這回合的日曆範圍之外、少了回應段，以及資料欄位名稱漏進正文。第 3 類是一串小毛病——中文敘事裡夾了英文單字、成績公布日之前就寫出分數、主角還不知道名字的人被提前寫出名字（index.html:11441-11490）。

這份清單讀起來像是一本真的發生過的失敗紀錄。條目會寫出是哪一段試玩人生的第幾回合；有一項檢查曾在某一天誤判、逼出 46 次重寫，之後被降為只記錄；還有一個偵測因為存檔查證幾乎全是誤報而被拿掉（index.html:11474、11500、11498）。這些代碼會隨下一次請求送回去，所以經營者可以統計。奇幻篇以縮小版重複了同一個做法：一個驗證器守著那個世界的一條規則，規則被打破時就退回事先寫好的文字（fantasy/engine/ai.js:99-103）。

有一個結果值得玩家知道。線上的奇幻篇序幕完全不會送到模型：正式網域會忽略測試用的網址參數，所以實際執行的是 mock.js 裡寫好的旁白——它的檔頭自己把這些文字稱為示範——取用一份標明已確認定稿、1,096 行的序幕文字檔（fantasy/engine/mock.js:1-3、fantasy/engine/prologueText.js:1）。更新紀錄寫明序幕每回合用一張稿紙；沒有寫這些文字是事先寫好的，而服務條款對遊戲的描述是「故事由 AI 接著寫下去」。這是對檔案行為的描述，不是對意圖的判斷。

smart_toyAI 輔助開發跡象

出貨物自己說了不少。執行時的故事由 Anthropic 的模型生成：前端仍留著 const MODEL = "claude-sonnet-5"（index.html:1068），後來的註解說模型已改由 Worker 決定；奇幻篇的本機測試模組列出 claude-haiku-5-5，並註明試玩與正式上線都用 Haiku（fantasy/engine/liveai.js:8-12）。隱私權政策寫明玩家輸入的文字會送給提供 AI 文字生成的第三方服務商，但沒有寫出名稱。關於程式是誰寫的，註解直接點名了工具：有 22 行寫著 使用者授權Claude全權判斷，更多行寫著 使用者同意Claude建議，另有 Claude Code判斷、ChatGPT開發審閱 與 claude.ai網頁版定案（index.html:2305、2339、7408、8154）。這些註解把人稱作「使用者」，讀起來是助理自己的口吻；「程式大部分是在一個人的指示下由 AI 助理寫成」是從這種措辭得出的推論，不是出貨物的陳述。因為沒有 repo，看不到任何共同作者署名。

總評

本次體檢中最繁複的人生模擬，也是唯一以付費服務營運的一款：一個語言模型被程式圍住，程式擲出每一個結果、截斷每一個數字、替每一則回覆打分類。工程判斷力很高，內務卻參差不齊——一支 27,704 行的檔案、只能姑且相信的測試、仍標為暫定的平衡，以及目前還只是寫好的序幕的第二個篇章。
