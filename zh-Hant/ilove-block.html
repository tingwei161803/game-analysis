七大面向

memory技術深度 6/10

規模很小，但蓋的順序是對的。engine.js 第一行就宣告自己是純狀態引擎——不碰 DOM、不碰網路，同一個 seed 加上同樣的操作就得到同樣的結果（engine.js:1）——程式也守住了這句話。mulberry32 亂數產生器把自己的狀態存在存檔物件裡（engine.js:20-26），所以讀檔之後接續的是同一串亂數；每個進入點（act、choose、buy、finish）都先複製狀態、再回傳新的（engine.js:211-212、826-827）。一個 step 迴圈把狀態轉成「現在該顯示的那一件事」：結果、事件、行動清單、考試或結局（engine.js:806-824）。可走動的那一層是 322 行 three.js，沒有任何模型檔。房間與角色用方塊、膠囊和球拼出來（world.js:32-51、78-110），燈光隨時段變化（world.js:182-188），點地板移動則是在 0.25 單位的網格上做廣度優先搜尋、不准切牆角，再用視線把路徑拉直（world.js:208-235）。three.js 或 WebGL 載入失敗時，遊戲會退回卡片選單而不是壞掉（world.js:5-10）。天花板是規模：JavaScript 總共 1,849 行、一週的內容、沒有需要解決的效能問題，卻載入 1.27 MB 未壓縮的 three.js 來畫方塊。

stadia_controller遊戲設計 8/10

這一週是一道帶著隱藏資訊的預算題。一天三個時段，熬夜可以多借一個，代價是睡眠債，隔天專注度會下降（engine.js:62、318-328）；科目越熟，讀書的進步越小（engine.js:72-76）。讓它不只是養成數值的，是那場考試。每一局都暗中挑一科佔 40%、其餘各 20%，另外再挑一個誘餌科目，以及一則只有一半機率為真的班群傳言（engine.js:46-55）。玩家查得出來：專心聽一次課會縮小到兩科，第二次就能確定；向室友換到考古題、或在電梯裡問出一個好問題，則直接揭曉（engine.js:425-436、587、730）。每一種都要花掉一個時段或一段交情。答應別人的事會變成在特定時段到期的約定，也可以反悔，但有代價（engine.js:556、570）。結局畫面列出遊玩過程中累積的「這週的因果」，然後問你會改變哪一件事（engine.js:84、ui.js:520-536）。九種結局先看健康、關係與回憶，再看分數（engine.js:900-914），所以考到高分卻耗盡體力，拿到的是「書卷的代價」，不是勝利。限制在於：平衡是手調的，背後沒有模擬或遙測；「相信傳言押寶」這個選擇寫入了一個從來沒有被讀取的值（engine.js:655-656）；而「不是一個人」這個結局只有在週六晚上選擇熬夜才可能開啟，遊戲沒有給任何提示（engine.js:841）。

security後端與安全 6.5/10

它沒有後端，頁面也這麼說：標題畫面印著「全程離線，不蒐集任何資料」，而出貨的三支 script 裡沒有 fetch、沒有 beacon，也沒有任何流量統計呼叫。狀態存在兩個 localStorage 鍵裡，每次存取都包在 try／catch 中，所以無痕模式照樣能玩（ui.js:55-59）；讀不回來的存檔會被刪掉並提示玩家，而不是讓遊戲卡住（ui.js:568）。three.js 是放在自己站上的，不從 CDN 拉；不存在的路徑會正確回 404。敘事文字在用 innerHTML 寫入之前都經過跳脫函式（ui.js:7）。壓低分數的有三件事。站台的 Content-Security-Policy 是以 report-only 送出，而且允許 'unsafe-inline' 與 'unsafe-eval'，實際上什麼都擋不了。有幾個取自存檔的值沒有跳脫就插入——考試加減分的標籤與結局標題（ui.js:498、524）——不過這只對「改自己瀏覽器儲存內容」的人有意義，因為程式完全不讀任何網址參數。另外，「離線」並非字面意義：頁面會向 Google Fonts 請求三套字型。

code程式品質 6.5/10

三個檔案、三份工作，各自在第一行寫明：純引擎、「只負責把 engine 的狀態畫出來、把玩家的選擇送回去」的介面層（ui.js:1），以及回報玩家碰了哪個互動點的場景模組。引擎同時匯出給 Node 與瀏覽器使用（engine.js:928）。事件的寫法一致、接近資料——一個回傳文字與選項的 build 函式，每個選項是一小段狀態轉移——所以 33 個事件只用了約 400 行。分層在幾個地方漏了：介面為了顯示預覽，自己重算了一次讀書進步的公式，而不是去問引擎（ui.js:360 對照 engine.js:73）；衝刺小遊戲的難度是在介面層決定的（ui.js:448）；考試途中的兩道提問也寫在介面層（ui.js:483-491）。此外還有殘留物：沒有匯出的 view 函式（engine.js:802）、只寫不讀的旗標（sprain、momLater、overslept、proxy）、教室座位表裡指向不存在角色的項目（world.js:127），以及把夜晚時段編成 2.5、介面層得用 Math.floor 繞開的寫法（engine.js:352、ui.js:134）。每一行都塞得很滿——有 49 行超過 300 個字元——模組之間靠 window 全域變數溝通，而不是 import。

experiment測試 2/10

沒有任何東西出貨，也沒有任何東西被提到：沒有測試檔、沒有測試工具、沒有 CI，也沒有任何一則註解點名它們；請求 package.json 與 tests 資料夾都回 404。這是投稿者的自評與這次閱讀完全一致的唯一面向。能替它說的話是：這顆引擎的形狀是為了它還沒有的測試而生的——作用在單純物件上的純函式、有種子的亂數、Node 匯出，還有一個公開即時狀態的 window.__game 把手（ui.js:597）。只要幾十行，就能重播一個 seed 並斷言結局，或者掃過隨機玩法來確認九種結局都走得到。但在實際送出的東西裡，這些都不存在。

verified完成度 7.5/10

一款完整的短篇遊戲。有可以接關的標題畫面、從頭到考試流程再到結局的完整一週、收錄九種結局與十六則回憶的圖鑑、記錄約定與考試風向的筆記、這一週的紀錄，以及玩法說明。玩法有兩種——在宿舍、教室與校園裡走動，或用卡片選單——隨時可以切換，鍵盤、數字鍵與觸控都有處理（ui.js:573-587、world.js:301-317）。十五張場景插畫與八張頭像在進度條後面預先載入；聲音是九種合成音效，靜音開關會被記住。script 與樣式表都尊重 reduced-motion。缺的是：音樂、任何能看到或分享 seed 的方式（「重來同一週」按鈕是它唯一的用途，ui.js:537-540）、版本號或更新紀錄、中文以外的語言，以及超過一週的內容。

emoji_objects原創性 7/10

題材是它自己的：醫學系大四生、以頁數計算的共筆、在週五總複習「不小心」講到考題的教授、直屬傳下來的考古題。框架則很熟悉——把一週切成時段、拿來養數值，是行之有年的生活模擬格式——而「走到物件旁互動」的呈現方式，程式與玩法說明都明白寫著參考了另一位創作者的值班模擬（world.js:2、ui.js:431）。新的東西在中間：一場配分必須自己去打聽的考試，附帶誘餌與不可靠的傳言，以及一個不是成績單、而是因果回顧的結局。插畫是 AI 生成的，玩法說明裡有寫。

trending_up亮點

  • 配分要自己打聽的考試——暗中有一科佔 40%，另有誘餌科目與一半機率為真的傳言；專心上兩次課、拿到考古題或在電梯裡發問都能揭曉（engine.js:46-55、425-436）
  • 有種子的純狀態引擎——亂數狀態存在存檔裡、每次轉移都回傳新狀態、可在 Node 匯入（engine.js:1、20-26、928）
  • 結局看的是這一週怎麼過——共九種，先看健康、關係與回憶再看分數，並附上因果回顧（engine.js:900-914、ui.js:520-536）
  • 不到三十行的尋路——網格廣度優先搜尋、不切牆角、用視線拉直路徑，卡住時重新規劃（world.js:208-235、272）
  • 「不蒐集任何資料」，程式也是這樣——出貨的 script 裡沒有任何網路呼叫，儲存存取都有包裝，無痕模式照樣能玩（ui.js:55-59）

trending_down弱點

  • 完全沒有測試——一顆純的、有種子的、可在 Node 匯入的引擎，卻沒有任何東西在驗證它，也沒有 CI
  • CSP 只是 report-only——而且允許 'unsafe-inline' 與 'unsafe-eval'，這份政策實際上什麼都不擋
  • 規則漏到介面層——重複的進步公式、衝刺門檻與考試中的提問都寫在 ui.js（ui.js:360、448、483-491）
  • 沒人讀的狀態——押寶傳言的結果有記錄卻從未被讀取（engine.js:655-656）、四個旗標只寫不讀、view 沒有匯出（engine.js:802）
  • 手調的平衡、只有一週——數字背後沒有模擬或遙測，還有一個結局藏在遊戲從未提示的條件後面（engine.js:841）
  • 取自存檔的值沒有跳脫——考試加減分標籤與結局標題直接進了 innerHTML（ui.js:498、524）；只有從玩家自己的儲存內容才碰得到

把自評對過一遍

這個專案是投稿來的。本站 repo 上的一則 issue 介紹了這款遊戲，預測測試與後端安全會是它最弱的兩個面向，並想知道讀過程式碼之後的評分會差在哪裡。它沒有公開的 repo，所以——和先前三個以出貨物受檢的專案一樣——改讀站台實際送出的檔案，日期是 2026-11-18。三支 script 都沒有壓縮。

測試的部分，預測完全成立：沒有東西出貨，也沒有東西被提到。後端與安全則不然。一款沒有伺服器、沒有網路呼叫、也不從網址讀取任何輸入的遊戲，可以攻擊的地方很少，而它對唯一的儲存機制處理得很小心；扣分是因為一個沒有強制執行的政策標頭，以及幾個沒有跳脫的值，不是因為暴露了什麼。這個面向落在全站的中段，不是墊底。

投稿沒有預料到的差距在別的地方。扣掉測試之後，最低分是技術深度——不是因為哪裡做得不好，而是這 1,849 行分層清楚的程式，還沒有遇到需要解決的難題。最高分則是遊戲設計，靠的是一個點子：一場配分要自己去打聽的考試。
