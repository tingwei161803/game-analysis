七大面向

memory技術深度 8.5/10

本次體檢工程最深的一款，而且大半深在連線。出貨的三個大檔開頭都有一行標頭，說明它們是由 make-sim.cjs 從編號的原始碼片段產生的——TypeScript 的 global script 去掉型別後由自製工具串接，沒有 bundler——註解寫明房間跑的是同一份原始碼產出的 sim.generated.mjs（i18n.js:9-10），所以瀏覽器與伺服器共用一套規則，而不是各寫一份。客戶端每 33 ms 或輸入改變時送出輸入（room.js:7），自己的揮擊先在本地預測並記下來供對帳（room.js:1355-1372），其他角色則依伺服器回報的「距上次報告過了幾個 1/60 秒步」沿上一段速度外插（room.js:1083-1090）。回放只存狀態、不存輸入：固定長度的數值列、差分壓縮，上限 280 KB 與一小時（replay-format.mjs:2-16）。渲染是單一 2D canvas、世界座標 1600×1200，沒有 sprite sheet——三個主檔合計只有 7 處 drawImage，全部是 UI 外框。唯一的軟肋：客戶端用上限 35 ms 的可變 dt（game.js:11629-11645），房間則是固定 1/60 秒步。

stadia_controller遊戲設計 8/10

四條勝利路線同時生效：接力送達九份文件、主席台累計四十秒、把票匭推到底，或打掉對方總召的三條命（team.js:60-178）。這是真的策略面——打架打輸的隊伍仍然可以靠接力贏。賽點被寫成狀態而不是事件：文件 7 份、主席台 31 秒或票匭軌道 0.6 時進入，票匭要退回 0.5 才解除（team.js:148-151），所以緊張感不會閃爍。數值刻意偏向真人——真人受到的傷害是 0.38 倍（新手引導期 0.28 倍），移動速度 205 對上 bot 的 155——對一款多數人在打 bot 的遊戲來說，這是誠實的調校。系列賽三戰兩勝。出貨程式沒有呈現的是量測：不像 YaKyoLife 的蒙地卡羅，也不像這一批另一款格鬥遊戲註解裡的模擬局數，這些門檻背後沒有勝率分布。

security後端與安全 7.5/10

本次體檢部署姿態最好的一款，但因為伺服器端程式本身看不到，分數打了折。從外部能查核的部分很嚴：CSP 是 default-src 'self'、唯一的 inline script 以 sha256 放行、frame-ancestors 'none' 與 object-src 'none'；COOP same-origin；Permissions-Policy 全關。整個客戶端只有四處 innerHTML，來源都是靜態字串或站方自己的翻譯目錄。流量統計是不用 cookie、不錄 session 的 PostHog（stats.js:1-4）。回放上傳有大小、時長與 id 格式的界限，失敗也不影響對局（replay.js:216-233）。功能旗標放在 KV，不必部署就能切換（/room/flags）。必須照單全收的部分：score-worker.mjs、聊天 worker 與設計 worker 只在註解裡有名字，從未送到瀏覽器，所以「伺服器權威」這個主張靠的是註解與行為，不是讀到的程式碼。

code程式品質 7/10

註解是這份程式碼最強的部分：講的是「為什麼」，附版本標記，還經常帶一個遙測數字。index.html 開頭記著 PostHog 在 2026-10-25 到 10-29 之間收到約 150 個 session 的「Can't find variable: i18n」，全是 iOS WebKit 的上一頁／下一頁載入，修法就是 CSP 用雜湊放行的那段 inline script（index.html:10-15）。compat.js:1-4 補上 Object.hasOwn polyfill，因為兩位用舊 iPhone 的玩家在 app 內建瀏覽器裡踩到。底下的結構就沒這麼有紀律：全部是共用同一個全域作用域的 classic script，29 個 <script> 依序載入、各自帶著互不相干的 ?v=（game.js?v=126、room.js?v=123、boot.js?v=57.28），後面的檔案靠重新指派全域變數去掛接前面的（replay.js:20-30、look.js:32-45）。而出貨的 game.js 還帶著史料頁說 v56.8 已經拿掉的波次與頭目闖關模式。

experiment測試 4/10

最難評的面向，因為證據是真的，卻是二手的。註解點名了至少十支檢查腳本——content-check（被引用 28 次）、team-sim.cjs、replay-box-check.mjs、compat-check.cjs、chat-check.cjs、i18n-check.mjs、score-worker-check.mjs 等——而且程式看得出是為了被檢查而寫的：navigator.webdriver 為真時固定角色與地圖，讓截圖可重現（game.js:3896-3899），window.musou.snapshot() 則把狀態交給測試工具。其中一支檢查有明確的來歷：v56.8 把勝利文件數從 8 調到 9，回放驗證的上限卻留在 8，於是每一場文件勝的回放都被拒收，到 v56.26 才修，現在由 replay-box-check.mjs 鎖住兩者相等（replay-format.mjs:13-15）。但這些腳本一支都沒有出貨，外人無法執行，也無從得知有沒有 CI 把關。這裡給的分數高於所有沒有測試的專案，低於任何測試讀得到的專案。

verified完成度 9/10

這是一個營運中的服務，不是 demo。兩種語言都完整（兩份各 1,105 行的目錄），有快速配對、房號不易看錯的私人房間、觀戰、全站聊天室、回放集、分享卡、只存在本機的生涯戰績（record.js:1-7）、換裝，以及四張輪替地圖。少見的是 /sources 頁：77 個條目、235 個外部連結，記錄每個角色的道具與招式出處，並附更正與下架的聯絡方式。公開的統計端點在受檢日回報約 9.4 萬場對局。缺口很小——沒有 PWA manifest 與 service worker——而文件已經開始與 build 脫節：史料頁還寫著十八位角色分三組、每組六人，出貨的名單則列了二十四位。

emoji_objects原創性 7.5/10

多目標的結構是借來的，而且自己講明了：史料頁把三路勝利條件、掩護與系列賽的想法署名給 Killer Queen Arcade，並聲明沒有搬用圖像、音效、程式或地圖。屬於它自己的，是填進這個借來框架裡的全部內容——把議場當競技場、把法案三讀當三條命、道具考據到需要一份參考書目——以及一件本站其他專案都沒嘗試的設計：用程式碼讓遊戲行為受選舉法規約束。遊戲中用的是戲仿名，真名只出現在史料頁。

trending_up亮點

  • 一份原始碼，兩份模擬——瀏覽器版與房間的 sim.generated.mjs 由自製的 make-sim.cjs 從同一批 TypeScript 產生，客戶端與伺服器的規則不會各走各的
  • 預測加外插——自己的揮擊先在本地預測，其他角色依伺服器回報的 1/60 秒步數外插（room.js:1083-1090、1355-1372）
  • 只存狀態、不存輸入的回放——差分壓縮的數值列，不含連線身分與使用者文字，上限 280 KB、保存 90 天（replay-format.mjs:2-16）
  • 選舉法規變成一條程式路徑——ELECTION_QUIET 與 ELECTION_DAY 兩個時間窗會藏起任何讀得出人氣高低的計數，並在投票日撤下以競選為題的地圖（game.js:3-9）
  • 用遙測數字論證的修正——每個繞道的註解都附日期、次數與機型，例如約 150 個 session 的 iOS 上一頁載入失敗（index.html:10-15）

trending_down弱點

  • 原始碼不公開、沒有授權——沒有 repo、沒有 LICENSE、沒有 source map；這裡的每個論斷都只能對照出貨的 build，伺服器端的 worker 則完全無法查核
  • 已移除的模式還在出貨物裡——v56.8 拿掉的波次與頭目闖關仍留在 game.js（28-70、3914-3925），look.js:8 還把它描述成可用
  • 29 支 script 共用一個全域作用域——產生出來的 game.js 有 11,730 行，載入順序是唯一的契約，後面的檔案靠重新指派全域變數去改前面的
  • 手動維護的 cache-bust 版本號——每個 script 標籤各帶自己的 ?v=，彼此編號不相干（?v=126、?v=123、?v=57.28）
  • 註解與文件裡的數字過期——名單是 24 人，史料頁寫十八、outfit.js:4 寫二十一、game.js:3897 寫十五

把選舉法規寫成程式

game.js 的頭幾行講的不是遊戲。它們定義了 2026-11-28 地方選舉前後的兩個時間窗，並各自引用法條：公職人員選舉罷免法第 53 條（投票前十日不得發布民調），以及第 56 條（投票日不得從事競選活動）（game.js:3-9）。

這兩個時間窗會改變行為。靜默期內不顯示任何可以被讀成「誰比較受歡迎」的計數；投票日則把以競選為題的地圖撤出輪替。另一條關於頭目名單的規則保證沒有政黨是預設的敵人，兩位互為對手的候選人也不會以最終頭目的身分對上（game.js:264-268）。註解提到伺服器端的 worker 帶著同樣的日期。

本次受檢日 2026-11-17 距離靜默期開始只有幾個小時，所以這裡描述的頁面在接下來十一天會有不同的行為。這是本報告中唯一把法律限制當成設計的一級輸入的專案——也是唯一讓「對在世公眾人物的戲仿」附上參考書目與下架聯絡方式、而不是一句免責聲明的專案。

smart_toyAI 輔助開發跡象

沒有 commit 歷史可讀，也沒有點名任何工具，但出貨的註解以第三人稱描述了一套由 agent 驅動的工作流。「the owner」這個詞在 JavaScript 裡出現 87 次，通常是引述一句口頭指示，再說明是怎麼實作的。lab.js:10 把內容產線形容為「the way the developers' agents added content: read an example, draft, check, fix, submit」。用的是哪個模型或工具，全案都沒寫。另外，遊戲本身也有一個 AI 功能——以 Cloudflare Agents SDK 與 Workers AI 做的武器設計器——目前被 lab 旗標關著。

總評

本次體檢工程最完整的一款，也是第一款沒有 repo 可讀的：伺服器端模擬的線上亂鬥、客戶端預測、只存狀態的回放格式、加固過的部署，以及兼作事故紀錄的註解。它的天花板卡在看不見的地方——伺服器端的 worker、檢查腳本、一份授權——以及一個到現在還出貨著自稱已移除模式的全域作用域結構。
