七大面向

memory技術深度 6.5/10

整款遊戲就是一個檔案；扣掉 1 MB 的 base64 美術和 600 KB 的 three.js 之後，底下是一顆由排程驅動的事件引擎。一個 40 ms 的 interval（index.html:12072）推動遊戲時鐘，現實三秒等於遊戲一分鐘（index.html:2199、12110）；每一分鐘會觸發到點的排程項目、延後的後續事件、檢驗報告與時限檢查（index.html:12128-12152）。每位個案帶著一份 schedule，每一項寫明事件 id、time 或 window、probability，也可以加 oneOf 或 excludeShifts；開班時由程式對照共用範本解析（index.html:4004-4062、9636-9652）。較新的事件把後果寫成資料——outcomes、deadlineMinutes、onExpire（index.html:3183-3189）。移動是在手工建立的走廊、門口、房內節點圖上跑 Dijkstra（index.html:10085-10200）。3D 病房是其中最巧的一段：一台傾斜 52 度的正交鏡頭，地面與 2D 舞台的百分比座標做仿射對齊（index.html:13402-13410），所以點擊、房卡與導航完全不用改；three.js 與場景程式放在 text/plain 的 script 標籤裡，頁面載入後才注入（index.html:13870-13879），WebGL 起不來就退回 2D 圖片（index.html:13828）。警報音以 Web Audio 合成，分成三級（index.html:2113-2150）。限制是結構上的：一個全域 gameState、70 處沒有種子的 Math.random、沒有模組，也沒有運算上真正困難的問題。

stadia_controller遊戲設計 8/10

它模擬的是護理師，不是病人。沒有任何一位病人有連續的生命徵象；病況是一疊事件卡，量 vital sign 時擲一張七列的表（index.html:3174-3182——從 8% 的高血壓到 0.2% 的無呼吸心跳），每位個案可以用 vitalRisk 調整各列的倍率（index.html:3476-3484）。玩家管理的是自己的壓力、體力、水分和欠著沒寫的紀錄，再加上病人安全與學姊人情度；四個門檻中任何一個到了，這一班就結束（index.html:12365-12372）。臨床內容寫得很具體。給藥在給藥時間前後一小時內完成才算準時（index.html:11466、9820-9827）。檢驗報告以五級判讀產生，危急值若只當一般異常處理，有 40% 的機率在 45 分鐘後演變成對應的急症（index.html:11017-11023、11090）。有一張醫囑是陷阱：胰島素 1000 U，交班回顧會說明那是一整瓶的劑量，必須先向醫師確認（index.html:11148）。下班前是一份逐床的交班測驗，題目取自這一班實際發生的事，干擾項是瑣事和與事實不符的「本班都穩定」（index.html:11546-11570）；接著是回顧，依各選項的 safety 數值替每個決策評等並附上解析（index.html:11486-11495、11141）。實習班安排了一次優先順序練習（index.html:9806-9813）。限制在於：所謂「正確」就是 safety 數字最高的那個選項，門檻值註明是遊戲設定（index.html:11009），而 README 記錄過某個階段機器人在六場白班裡有五場過勞昏倒。

security後端與安全 5.5/10

它沒有後端。Worker 的設定檔裡只有一條靜態資源設定（wrangler.jsonc："directory": "."），/api 回 404，程式裡沒有 fetch、XHR、beacon、WebSocket，也沒有任何流量統計呼叫，更不從其他來源載入任何東西——字型、美術與 three.js 全都在檔案裡。唯一會離開頁面的呼叫是分享結算圖用的 navigator.share，而且要玩家自己按（index.html:13220）。狀態是六個 localStorage 鍵，每次存取都包在 try／catch 裡，圖鑑資料損壞時會退回空白紀錄（index.html:9211-9220）；成就圖鑑也告訴玩家紀錄只存在這台裝置上。暱稱是用 innerText 寫進頁面的（index.html:9851、13247），交班回顧的各欄位有跳脫（index.html:11672）；唯一讀取的網址輸入是對 preview=1 的正規表示式比對（index.html:8978）。意見回饋表單直接說明它不會送出任何東西（index.html:13062）。壓低分數的有兩件事。首頁沒有送出 Content-Security-Policy、HSTS、X-Content-Type-Options，也沒有任何防嵌入的標頭。另外，因為資源目錄就是專案根目錄，部署出來的站台對 README.md、wrangler.jsonc、.gitignore 與 .git/HEAD 也都回 200；在讀過的檔案裡沒有看到敏感內容，.git 的內容則沒有去抓。不存在的路徑會正確回 404。

code程式品質 5/10

讀得懂、也有註解，但它是一層一層疊上去、從來沒有合併過的。決定「接下來發生什麼」的機制有兩套同時存在。較新的事件宣告 outcomes，以遊戲時鐘上的 delayMin 排程；較舊的事件則是在 selectOption 裡長達約 250 行的區段中，依選項旗標手寫分支，並用現實時間的計時器排程——15 分鐘後複測血糖寫成 setTimeout(…, 15000)（index.html:11774-11782），既不理會遊戲倍速，也不理會暫停。體力消耗是事後拿目前值和上一次的值相比再縮放（index.html:12356-12360），而不是在每個來源處理。結局是用正規表示式比對顯示文字來辨識的（index.html:9154-9176、11641-11647），所以英文版連這些樣式都得一起翻譯。術語圖鑑在啟動時由 FIX、DROP、ADD 三份清單修補（index.html:12846-12913）。有一則註解寫著入院功能「目前為 false」，往下兩行卻是 enabled: true（index.html:12401、12403）；openMemorial 有定義但從未被呼叫（index.html:8983）。全檔有 26 個空的 catch 區塊與 85 個行內 onclick。另一方面：範本解析集中在一個清楚的函式（index.html:4004-4062），調校用的常數都有命名與說明，62 個 commit 都很小、訊息也寫得具體。更大的問題是這個 repo 放的是建置產物——README 說要改的是 data/patientPool.json、src3d/scene3d.js 和 tools/ 底下的腳本，這些都沒有公開。

experiment測試 3.5/10

目前的檔案樹裡沒有測試，也沒有 CI，但歷史顯示測試確實做過。有一個檔案被 commit 進來，三個 commit 之後又被移除，訊息說那是誤加的、測試檔只放在 zip 裡（f1a49ae）；現在仍然可以用 git show 26f8efe:tests/smart_playtest.py 讀到。那是一支 156 行的 Playwright 腳本，在虛擬時鐘下透過真正的頁面把整個班打完：會買道具、喝水、補紀錄，依選項的 safety 數值、以三種程度作答（expert、75% 選最佳的 average、45% 的 rookie），最後還會勾交班單。它包住 ringRoomAlarm、handleEventExpiry 與 triggerEndShift 來記錄每一個事件，會標出時鐘凍結或「事件沒有任何可按選項」的狀況，也會收集頁面錯誤。它不對結果下任何斷言；這是一支平衡探測器兼卡關偵測器。README 另外點名了十七支腳本（schedule_check.py、vital_check.py、ward_check.py、discharge_check.py 等），並引用機器人跑出來的結果作為調整依據——例如 36 場之中膀胱炎結局從 13 場降到 3 場。這些腳本一支都讀不到，所以只能算「被提到」，不能算證據。頁面裡留有一個「只給自動測試用」的 gfxForce2D 開關（index.html:13866）。

verified完成度 8.5/10

這是一款做完了、可以重玩的遊戲，周邊內容比這裡大多數專案都多。四種班別——顧四床的實習班、八床的白班、十二床的小夜、十六床的大夜（index.html:2211-2215、11322）——從 35 位寫好的個案裡抽人，這些個案一共帶著 653 筆排程項目，每一位都有病史、家庭背景、性格與護理重點，照護過之後會在個案圖鑑裡解鎖。事件表裡共有 143 個帶字母的選項，另有 22 種收錄在圖鑑的結局（index.html:9154-9177）、29 個稱號、家屬感謝卡、可搜尋的術語圖鑑、各班別第一次上班前的學姊叮嚀、有十二種道具的上班前商店、做成多步驟連鎖的入院與出院、大夜每兩小時的巡視、鍵盤快捷鍵、直向／橫向／桌面三套版面、一條 reduced-motion 規則（index.html:1178）、1080×1920 的結算分享卡，以及一份由中文版產生的完整英文版。免責聲明出現在開始畫面（index.html:1680）、meta description 與分享卡上。缺的或粗糙的地方：班上到一半不能存檔、意見回饋按鈕被隱藏（index.html:1664）、沒有授權檔、頁面上沒有版本號、依 README 自己的說法英文版的薪資圖仍是中文，而 README 開頭還是舊的名稱，資料夾說明表列的也是 repo 裡沒有的檔案。

emoji_objects原創性 7.5/10

題材是它自己的：從最菜的護理師眼中看出去的血液腫瘤科病房，用的是病房裡真正在講的行話——把壓傷叫「杯叟」、「New Pe」、「抽血神人學姊」——笑點也只有上過班的人才接得住，例如結算畫面會把今天剩下的薪水換算成買一間房要上幾年班（index.html:13268-13276）。框架則是熟悉的：限時警報、帶字母的選項與資源條，都是經營模擬的標準配備；3D 畫面的風格，註解裡寫的是參照一款知名的合作廚房遊戲（index.html:13402）。新的東西在那些從工作本身長出來的機制：把水分和沒寫的紀錄當成資源、給藥時間窗、一張預期玩家要拒絕執行的錯誤醫囑，以及把交班做成計分的最後一關。頁面和 README 都沒有提到以其他醫療模擬作品為藍本。README 自己的待辦清單倒是記著，較早的開始畫面在版型與文案上和另一款作品太接近，後面的條目則說已經換成原創的名稱與設計；同一份清單也談到美術是仿某位插畫家的風格製作，遊戲內沒有出現那位插畫家的名字。內嵌美術與那張薪資表照片的來源，檔案裡沒有說明。

trending_up亮點

  • 把交班做成期末考——下班前每一床都有一份依這一班實際事件產生的勾選單，干擾項是瑣事和與事實不符的「本班都穩定」；整床全對才算（index.html:11546-11570、11599）
  • 每個選擇都有解析的回顧——決策依選項的 safety 數值評為最安全／可以更好／有風險，每個選項各有一段文字說明（index.html:11486-11495、11141）
  • 個案就是資料——35 位病人各有一份涵蓋 24 小時的 schedule，寫明事件 id、時間或區間與機率，再對照共用範本解析（index.html:4065、4004-4062）
  • 不動規則、把 3D 墊在 2D 底下——正交鏡頭對齊舞台的百分比座標，載入後才從 text/plain 的 script 標籤注入，並可退回 2D（index.html:13402-13410、13870-13879）
  • 完全沒有網路呼叫——2.3 MB 的頁面裡沒有 fetch、追蹤碼或外部字型；只用 localStorage，意見回饋表單也明說不會送出（index.html:13062）
  • 免責聲明出現在三個地方——開始畫面、meta description 與分享卡都寫著僅供娛樂與教育、非臨床指引（index.html:7、1680、13202）

trending_down弱點

  • 遊戲時鐘的模擬裡混著現實時間的計時器——較舊的後續事件用 setTimeout(…, 15000) 代表「15 分鐘後」複測，不受倍速與暫停影響（index.html:11776-11782）
  • repo 裡放的是建置產物——README 說要修改的是 data/patientPool.json、src3d/scene3d.js 與 tools/；repo 只追蹤五個檔案，這些都不在其中
  • 測試只留下痕跡——一支機器人腳本 commit 後又被移除（f1a49ae），README 另外點名十七支，檔案樹裡一支都沒有，也沒有 CI
  • 專案根目錄就是網站根目錄——wrangler.jsonc 發佈的是 .，所以 README.md、wrangler.jsonc、.gitignore 與 .git/HEAD 都回 200；也沒有送出任何安全標頭
  • 用顯示文字來比對結局——結局圖鑑與表現分析都是拿正規表示式去比對結局那句話（index.html:9154-9176、11641-11647）
  • 補丁疊補丁——體力消耗事後再縮放（index.html:12356-12360）、啟動時才修補的術語圖鑑（index.html:12846-12913）、enabled: true 上方還留著「目前為 false」的過期註解（index.html:12401-12403）
  • 沒有列出臨床依據——解析寫得很細，但沒有引用任何指引；註解說門檻是遊戲設定、請以各院規範為準（index.html:11009、11140）

一份寫給看不到的專案的 README

公開的 repo 只追蹤五個檔案：兩個 HTML 頁面、兩張圖，以及一份 332 行的 README。但 README 描述的是一個大得多的專案：放在 data/patientPool.json、由 Python 腳本嵌進頁面的個案表，以同樣方式嵌入的 src3d/scene3d.js 3D 場景，tools/i18n/ 底下的翻譯流程，docs/ 裡的設計手冊，一份封存的 React 舊版，還有一個測試資料夾。這些都沒有公開。公開的是那條流程的產出，每改一次就 commit 一次。

測試最能看出這個落差。README 點名了十八支測試腳本，也記下試玩機器人跑出來的結果。其中真正進過 repo 的只有一支，三個 commit 之後就被刪掉，訊息說那是誤加的、測試檔只放在 zip 裡。因為 git 會保留歷史，那個檔案現在還讀得到，而且它是一支真的會把整個班打完的機器人，不是空殼。

對讀者來說，這件事有兩面。頁面沒有壓縮、歷史也是公開的，所以實際執行的每一行都讀得到。但這裡的程式碼品質與測試分數，評的是被公開的那份產物；它背後那個真正在運作的專案——能看出資料怎麼維護、檢查做到什麼程度的那一部分——只有被描述，沒有被拿出來。
