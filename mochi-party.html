Overview / Mochi Party (unsigned)

Mochi Party

Five co-op party games for four phones under one lobby: lay road ahead of a food truck, survive 78 three-second microgames, sneak through a haunted school, cook a forest banquet, haul fragile furniture. The browser only sends input; a Rust server runs the games, and solo play runs the same simulation on the phone as WebAssembly, with the server replaying the input log before it pays out rewards.

The seven dimensions

memoryTechnical Depth 8.5/10

Four of the five games are thin clients over an authoritative server: web/main.js:1 opens with a comment that the client only sends input and draws the state the server sends, and the input loop emits one {t:'in',x,y,b} message on change or every 0.2 s (web/main.js:845-846). Comments describe the server as Rust crates that replaced an earlier Go version (web/hints.js:4). The standout is solo Road Truck: the same simulation ships as WebAssembly, wrapped in an object shaped like a WebSocket so the renderer is untouched, stepped every 50 ms; at the end the client uploads ticket, version, setup, input log and claimed outcome, and the server replays it before paying rewards (web/localroad.js:1-6, web/localroad.js:153). Room traffic uses a hand-built protocol: one raw-deflate stream per connection, plus client-side frame synthesis that reproduces idle frames from per-number rates and inserts a midpoint frame when the server skips one (web/meta/wsz.js:1-12, web/meta/wsz.js:42-68). Reconnection replaces a stalled socket instead of racing two, because Chrome serialises handshakes per host (web/meta/api.js:98-113). Per-frame allocations are hoisted into constants by code generators (web/render.js:25, web/render.js:46). Limits: nothing is bundled — the home page's static import graph is 92 files, about 2.8 MB before Brotli, all served cache-control: no-cache — and neither the server nor the .wasm was read.

stadia_controllerGame Design 8/10

Each game takes a familiar co-op template and adds a rule that turns failure into a joke rather than a wall. In Road Truck a crash triggers the Blame Court: a replay plays, players vote on the culprit, and the loser wears a duck head for a stretch (web/i18n.js:205, web/i18n.js:521); the results screen is a news bulletin assembled from the match's event log (web/i18n.js:645-646). In Night School Ghosts a caught player is not eliminated but becomes a prankster who switches off lights and slams doors on teammates (web/ghost/i18n.js:8-9). Forest Feast states that there is no failure, only a rowdier party (web/banquet/i18n.js:7). 3-Second Scramble lists 78 microgames in five themes, 14 of them split across four phones and 10 using tilt, shake or microphone with a touch fallback (web/micro/games/index.js:4-27), and its runner sub-steps slow frames at 1/60 s so a tap is judged against the picture at the moment it happened (web/micro/play.js:39-43). Accessibility is designed in: an Okabe–Ito colour-blind palette, font scale, reduced motion (web/meta/settings.js:4-6) and an easy mode that keeps stars and unlocks (web/i18n.js:14). Limits: the balance numbers live on the server, the client shows no sign of measured tuning, and this audit read the games rather than played them.

securityBackend & Security 7.5/10

The largest server surface in this audit — the client names 111 distinct /api/ paths covering sessions, friends, chat, reports, bans and appeals, mail, purchases and push — and none of it can be read, so the score rests on posture and on what the client is allowed to do. Headers are strict: a CSP with default-src 'self' that admits only Google sign-in as a third-party script (styles do allow 'unsafe-inline'), one-year HSTS, nosniff, and a Permissions-Policy that leaves only microphone and motion sensors open to the site itself. Missing paths return a plain 404; there is no robots.txt. The login token travels in an Authorization header and in the WebSocket subprotocol, not the URL (web/meta/api.js:39, web/meta/api.js:66-69), and the ?pid= test override is honoured only on local hostnames (web/meta/api.js:15-18). A random device id is kept in localStorage, IndexedDB and a 400-day cookie that restore one another, for guest-account limits and ban enforcement (web/meta/api.js:232-234); the privacy policy discloses it. No analytics or tracker code was found, matching privacy.html:60. Hygiene notes: microgame results are reported by the client by design (web/micro/main.js:2), /api/info returns the container image reference, and the policy calls Cloudflare DNS-only (privacy.html:74) while index.html:8-11 says icons and preview images moved to Cloudflare Pages on 2026-11-03.

codeCode Quality 7/10

The comments are the best documentation in this audit: they give the reason, the device and often a measurement. web/meta/api.js:98-107 explains the reconnect design from a named phone on Android 15 over 4G, including TCP's 1 → 3 → 7 second SYN retries; web/audio.js:6-11 records why AAC files carry an .mp4 extension. The layout is real ES modules, one folder per game plus a shared meta/, with cross-references to 15 distinct sections of a CONTRACT document. Failure is contained: a microgame file that fails to load removes only that game (web/micro/games/index.js:29), and a draw error is caught and the canvas state restored (web/micro/play.js:89). The debts are structural. onSnap in web/main.js:431-600 is one 170-line chain of effect-key conditionals; 1,045 lines exceed 250 characters; 192 distinct window.__* globals exist, many of them test hooks living in production (web/main.js:82-121); the production character renderer is served from a folder named demos/, whose first file still opens with the header of a pitch-animation stage (demos/stage.js:1-13); and language detection is copied into each game's i18n.js. The shipped files are also the output of the allocation-hoisting generators, which leaves artefacts such as web/micro/games/fly.js:176 reading _K20.rot from an object defined at line 41 without that field.

experimentTesting 4/10

Tests are named throughout the client but none are shipped, so this sits at the ceiling for second-hand evidence. The names are specific: cargo test -p meta --test cosaudit as a release gate for cosmetics (web/meta/roomfx.js:6), server-rs/crates/meta/tests/retier.rs::rarityfx_tables checking a client table against the catalogue item by item (demos/rarityfx.js:201), a WebAssembly-versus-server parity entry point (web/roadsim.js:1, web/roadsim.js:42), and browser-driving tools cdp.mjs and playtest.mjs (web/render.js:1724, web/meta/wsz.js:176). The code is visibly built to be driven: the phrase for screen test appears 75 times, window.__state exposes a read-only deep copy of the whole game state (web/main.js:82-121), every microgame implements auto(want) so a bot or harness can aim to pass or fail it (web/micro/play.js:6), and even the service worker has a hook for clicking a notification in headless Chrome (sw.js:56-57). The solo-verify path is also a determinism check running in production: if the phone and the server disagree on a replay, no reward is paid (web/localroad.js:164). What cannot be told from outside is how much the tests cover, whether they pass, or whether anything gates a deploy.

verifiedCompleteness 9/10

A live service with the full apparatus around the games. One lobby leads to five games through party rooms, quick-match queues and friend invitations; bots fill empty seats. Around that sit guest accounts with Google, LINE and Apple linking, friends and chat with a word filter mirrored from the server (web/meta/chat-filter.js:1-2), reports, bans with an in-game appeal, a mailbox, quests, a season pass, a gacha with a published odds table and pity counters, redeem codes, web push, and a wardrobe of cosmetics drawn in code. Everything is bilingual, including the privacy policy, terms and support page. Comments describe an iOS Capacitor app and an Android TWA where purchases happen; the web build shows prices but takes no payment (web/meta/pay.js:4-8). Content is broad: 78 microgames, 7 ghost levels, 12 banquet levels, 15 moving levels (web/ghost/i18n.js:254, web/banquet/i18n.js:202, web/moving/i18n.js:287). The gaps are small and mostly self-declared: boss music is not produced yet and falls back to another track (web/audio.js:15, web/audio.js:22), the PWA icons are marked provisional (index.html:24), the service worker does push only and no offline cache (sw.js:1-2), and 18 microgames ship but are not drawn by the server unless a switch is on (web/micro/games/index.js:18).

emoji_objectsOriginality 7/10

The five frames are established co-op genres — laying a route ahead of a moving vehicle, a rapid-fire microgame gauntlet, a shared kitchen, furniture hauling, an escape from a haunted building — and the site has no credits or inspirations page; the only named reference in the code is a comment calling the gacha reel CS:GO-style (web/meta/gacha.js:1). What belongs to this project is what connects and fills the frames. One mochi character, drawn entirely from parameters such as squash, lean and pull (demos/mochi.js:1-12), carries the same wardrobe through all five games. The Blame Court turns the worst moment of a co-op round into a vote over replay evidence, with evidence lines written per creature (web/i18n.js:245). Results are read out as a news bulletin in a synthesised mochi babble rather than text-to-speech (web/main.js:74). Microgames that split one picture across four phones are a format the genre's single-screen ancestors could not do. And the gacha comment records a restraint: the reel is filled at the published odds and rare items are not placed next to the result (web/meta/gacha.js:1). The collection is assembled from borrowed shapes; the tone and the connective systems are its own.

  • A privacy policy written from the code — an HTML comment says it was rewritten on 2026-10-05 from the program's actual behaviour (privacy.html:16-19), and the claim of no third-party analytics matches both the CSP and a search of the client.

The phone runs the game, the server replays it

Most server-authoritative games pay for that authority with a live process per room. Solo Road Truck does it differently. The client asks the server for a ticket carrying a seed and a version, loads road.wasm, checks that the version matches, and steps the simulation locally every 50 ms. web/localroad.js:3 says the messages it produces are character-for-character the same as a server room's, which is why the renderer needs no changes: LocalSocket exposes send, onmessage and readyState like the real thing. When the round ends the phone uploads the ticket, the setup, the input log and the outcome it claims; the server recomputes and grants rewards only if the two agree.

The failure paths are thought through rather than assumed away. No WebAssembly support, a failed download or a version mismatch each fall back silently to a normal server room (web/localroad.js:74-87). If the verifier is busy the client retries eight times, then stores the result on the device for up to 70 minutes and resubmits it before the next round (web/localroad.js:13-16, web/localroad.js:172-176). A comment in index.html:8-11 gives a likely reason this matters: preview images were moved off the game host because crawlers kept waking a server that had shut down with nobody playing.

The caveat is the usual one for this audit: the verifier is on the server and was not read. What the client shows is the shape of the contract — a ticket, a version check, a deterministic step function, an input log — and that shape is consistent with replay verification being real.

Verdict

The most complete and most deeply engineered project in this batch, and the one where the least of the engineering can actually be read. The client alone is about 79,000 lines across five games and a full account, social and store layer, with netcode decisions explained from measurements on real phones and a verified local simulation that few projects of any size attempt. The scores are capped where the evidence stops: the Rust server, the WebAssembly module and every test live out of sight, and what is visible carries the marks of fast growth — unbundled delivery, test hooks in production and folders still named after a prototype.
