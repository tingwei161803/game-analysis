Overview / aioo

One-Shot Parking

A Taiwanese car driving-test simulator that turns the official deduction tables into code: eight closed-course stations plus five road segments, automatic or manual, judged in fixed 1/120 s steps — and re-tuned across thirty releases in four days from its own anonymous pass-rate data.

Dimension by dimension

The seven dimensions

memoryTechnical Depth 8.5/10

The simulation is deterministic by construction. car.js opens by stating that it is pure — no DOM, clock or randomness — and that every call is cut into substeps of at most 1/240 s, so the same inputs give the same path at any frame rate (car.js:1-3); judging runs in fixed 1/120 s substeps with the remainder carried to the next frame (engine.js:1-5). The car is a kinematic bicycle model referenced at the rear axle (car.js:247-256). The manual gearbox is where it goes further than a toy: the clutch is solved as stick-slip friction each substep — the impulse that would equalise engine and disc speed, clamped by engagement × 260 Nm — with a torque curve, an idle controller and a stall below 500 rpm (car.js:300-332). The share video is produced entirely on the device: the replay is re-shot from several cameras, encoded with WebCodecs, and written out by a hand-rolled ftyp/moov/mdat muxer, with cuts aligned to a 120 BPM track (highlight.js:1, 1133-1209). There are no model or texture files at all; the course is drawn from station data and the engine note is synthesized in Web Audio.

stadia_controllerGame Design 8.5/10

The rules are not invented; they are transcribed. rules.js:4-16 names the two official scoring sheets the game follows — the closed-course table from the Executive Yuan Gazette (2026-03-31 edition) and the 2017 road-test table — and the deduction catalogue beneath is laid out item by item against them. What the game cannot sense it says so: riding the brake with the left foot and one-handed steering are in the table flagged sensed: false (rules.js:92, 94). What the government does not publish, such as course dimensions, is marked // game setting wherever it appears, hundreds of times across the code, so official numbers and the author's numbers never blur. Difficulty is then tuned from data and the comments keep the receipts: about 18,600 results in v0.1.18 showed 23% passing reverse parking (practice-hints.js:2-5); an S-curve built to a driving-school blog's dimensions was passed by 2% of the players who reached it, then 3% after a first fix, before the bends were redrawn around the car's own full-lock circle (stations/scurve.js:17-25). The comedy layer — examiner reactions, quips — only reads the run and adds no deduction (fx.js:1-8).

securityBackend & Security 6.5/10

A small surface, handled carefully on the client and opaque on the server. Only three same-origin endpoints exist: an anonymous event beacon, a counter read, and a call that issues the serial number on the souvenir licence. Privacy is better than most projects here: the beacon is disabled outright under Do Not Track or Global Privacy Control (stats.js:184), identifiers are two random values that rotate per page load and per day, events pass an allow-list cleaner, and the rules page lists what is sent in terms that match the code. Response headers are strict (script-src 'self', object-src 'none', HSTS) and the game's own JavaScript contains no innerHTML or eval at all. Two things pull the score down. Results are judged on the client, and the licence request carries only a claim id and the transmission type (license.js:176-182) — nothing ties a serial number to a run that actually passed. And requests for paths that do not exist return HTTP 500 with a Worker exception code instead of 404. The Worker's source, storage and rate limiting are not visible.

codeCode Quality 7.5/10

The best-layered code in this batch: the simulation core is pure functions, the engine judges, the scene draws, controls sample input, and the app shell wires them together, with dependencies injected so modules can be imported under Node. Saves are read through repairing cleaners and re-read before every write so a stale tab cannot overwrite progress (records.js:15, 75-89). Comments explain decisions and cite an internal planning vocabulary. The debts are specific. Two files carry too much — scene.js at 5,298 lines and app.js at 3,873. And every one of the 247 import specifiers still says ?v=0.1.0 although the game is at 0.1.29, so freshness depends on must-revalidate and ETags; the code works around the resulting mixed-version risk by switching to namespace imports that tolerate a missing export (stats-flow.js:6-8). YaKyoLife hand-maintains its cache-bust tokens; this project stopped maintaining them and built a guard instead.

experimentTesting 4/10

No test file ships, and no CI can be observed, so this cannot score as a tested project. It scores above the untested ones because the artifact is shaped by tests that the comments name precisely: tests/fx.test.mjs pins the rule that the comedy layer never changes judging (fx.js:6), station tests exist for the S-curve and the garage, and two helpers are described — an autopilot that drives perfectly, and a 'pupil' with a reaction delay used to sweep difficulty. One comment gives its result: with a 1.5 s reaction, the old quick-challenge start parked 2 times in 15 and the new one 11 (garage-challenge.js:5-13). The architecture is consistent with that story — pure modules, injected fetch, storage and clock. But an outsider cannot read, run or count any of it.

verifiedCompleteness 9/10

Shipped to product grade in its first week. Two licence classes, automatic and manual, a practice mode with step-by-step hints, a replay viewer with a scrubbable timeline, slow motion and camera changes, share cards in three sizes, a challenge link, the on-device highlight video and two souvenir licences. Keyboard and touch controls are both complete, the clutch can be moved to either side of the screen, and reduced-motion is respected. Quality adapts in four tiers, dropping a tier when the median frame rate stays under 25 fps and pinning it if an upgrade fails, so phones do not recompile shaders in a loop (scene.js:1552-1563). The rules page runs to roughly twenty thousand characters: the deduction tables, their sources, a section on what the game cannot do, and a data-collection FAQ. An in-game changelog lists all thirty releases in plain language.

emoji_objectsOriginality 7.5/10

Driving simulators are common; this particular thing is not. The subject is Taiwan's own two-part car test, the rule engine is the government's scoring sheet transcribed item by item, and the code labels every number the government did not supply. That is closer to a faithful model of a public procedure than to a genre entry. The frame is inherited, openly: the audio module says it was forked from the same author's scooter-test game, and 'moto-parity' recurs in comments as a requirement. A new subject on a chassis the author already owned.

trending_upHighlights

  • Difficulty tuned from pass rates, with the numbers in the comments — 23% on reverse parking across ~18,600 results, 2% then 3% on the S-curve before it was redrawn (practice-hints.js:2-5, stations/scurve.js:17-25)
  • A highlight video made on the device — WebCodecs H.264 plus a hand-written MP4 muxer, cut to the beat, nothing uploaded (highlight.js:1, 1133-1209)
  • A stick-slip clutch that can stall — engine inertia, friction capacity scaled by pedal engagement, torque curve and idle control (car.js:300-332)
  • The official scoring sheet as data — gazette sources cited in code, and items the game cannot detect flagged sensed: false rather than quietly dropped (rules.js:4-16, 92)
  • Telemetry that honours DNT and GPC — the beacon is off entirely under either signal, and the public FAQ matches what the code sends (stats.js:184)

trending_downWeaknesses

  • Source, tests and Worker are all private — no repository and no licence; every pass rate and test named in the comments is the author's own account and cannot be reproduced
  • Results are self-reported — the licence request carries a claim id and transmission only, so a serial number is not bound to a passed exam (license.js:176-182)
  • Missing paths return 500 — a request for a file that does not exist surfaces a Worker exception instead of a 404
  • 247 frozen cache-bust tokens — every import still says ?v=0.1.0 at version 0.1.29, with namespace imports added to survive mixed versions (stats-flow.js:6-8)
  • Two oversized files — scene.js at 5,298 lines and app.js at 3,873, in an otherwise well-separated codebase

Three games with no repository

This is the first of three projects in this report for which no public repository could be found. The earlier eight were cloned with full history; these three were read from what the server actually sends to a browser, on 2026-11-17.

That turned out to be enough for a line-level reading, for the same reason in all three cases: none of them minifies. This one ships 63 ES modules exactly as written, with no build step, so the design rationale, the internal plan numbers and the pass rates behind each tuning change are all in the response body.

It is also where the wall is. Git history, commit counts, the test suite and the server code stay private, so those fields read 'unknown' on these three pages rather than zero, and testing scores are capped: a test that is named but cannot be read is credited as evidence of process, not as verification.

smart_toyAI-assisted development

No tool is named anywhere in the shipped files. What the comments do carry is the vocabulary of a planned, multi-task build with one person approving: 'plan convention', 'Pinned interfaces', task numbers, wave numbers, and numbered rulings — fx.js:4 cites 'ruling R6', and quips.js:2-3 says the jokes 'are drafts for the owner to approve (ruling R7)'. That reads like agent-style development under a single owner's review, but it is an inference from wording, with no commit history to confirm it.

Verdict

A driving-test simulator that treats a government scoring sheet as a specification and its own telemetry as a test bench: deterministic physics, a clutch that stalls honestly, video encoding on the device, and thirty releases in four days each argued from a number. What it lacks is everything an outsider would need to check that story — a repository, a runnable test, and a server that verifies the result it certifies.
