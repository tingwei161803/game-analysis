15 ways to ship

The same era, the same AI-assisted tooling, many different philosophies — one optimizing for velocity, one for institutional continuity, one for measured balance, one that inherited a format and re-skinned it, and three that keep their source private while running a live game: tuned from telemetry, run as a hardened service, or logged in the open inside a single file. The newer entries widen the range further: an offline game that asked to be audited, a paid AI storyteller, a party platform with a Rust server, an election model, a quiz, a nurse's shift and a teacher's year.

craig7351 (Book AI)

Solo developer + AI pair

Five 3D browser games shipped in 36 days (2026-06-12 → 07-18), every one deployed live with a real Cloudflare D1 backend — leaderboards, message boards, online-presence charts. 248 commits, ~29k lines of hand-written code, and effectively 100% of commits co-authored by Claude (Opus 4.8 for the first four, Fable 5 for the fifth).

The signature workflow: a human directing design, verifying on real devices and handling real-world constraints (free-tier quotas, iOS quirks), while the AI produces code at burst cadence — 63 commits in a single day at peak. The repos double as artifacts of this workflow: reskin playbooks, READMEs written for 'the next AI', a custom Claude skill, even a prompt-injection incident report.

Consistent strengths: completeness and game feel, plus unusually mature free-tier cost engineering. Consistent debts: zero-to-minimal testing, god-file architecture, and a recurring weak-password signature ('0501') that leaks into public repos.

Open Culture Foundation (OCF)

Nonprofit organization

One project maintained over 22 months (2024-09 → 2026-07): a digital-security curriculum for Taiwanese civil-society organizations, run as institutional infrastructure — shared org account, PR reviews with issue references, issue templates, deploy-branch strategy, scoped tokens, CC-BY 4.0 licensing.

Where the solo author optimizes for velocity, OCF optimizes for continuity and audience fit: written editorial rules, a policy template mapped to Taiwanese NGO governance, Tor access for at-risk users — and a late-2026 burst that quietly added a 7,600-line 3D teaching game.

Leo Chang · 最先生 (LeoGGcat)

Solo creator + collaborator + AI

One game, 18 consecutive days, 267 commits and 32 released versions (2026-08-07 → 08-24) — a text-only Taiwanese baseball career sim shipped on its own domain as an installable PWA. The workflow is a hybrid no other author here uses: the owner (credited in-game as 最先生 Mr.TheMost) directs design, a second developer contributes through pull requests, and Claude is the commit author on 39 commits and co-signs 30 more.

The signature is measurement. Balance is not tuned by feel but re-derived from full-flow Monte Carlo runs — thousands of simulated careers used first to prove the old Hall-of-Fame thresholds were mathematically unreachable, then to re-anchor the whole ladder to explicit population targets. The code carries the same habit: comments justify decisions with numbers (contrast ratios, measured season counts, surgery frequencies) instead of restating what the line does.

Consistent strengths: domain-modelling depth, comment quality and product-grade finish (four themes, PWA, share card, wiki, changelog). Consistent debts: no tests, no CI, a calibration harness that never entered the repository, and 173 hand-maintained cache-bust tokens standing in for a build step.

jarvanthevoyager

Solo producer, borrowed format

One game in a single 3,500-line HTML file, published through the GitHub web UI in 17 commits across four days — 'Add files via upload', 'Update index.html'. That history is therefore not a development history at all: the work happened off-platform, and the artifact is the only evidence of how it was built.

The README credits the original concept to 最先生 (@mr.themost) — the designer behind YaKyoLife. This is a format handed to a second producer: the same seeded-life chassis re-skinned onto cheer-squad careers, a subject with no obvious prior example. What the producer adds is output discipline (consistent escaping, cookieless analytics, a documented storage table) and the audit's only shipped integrity checker.

The trade-off is legibility and provenance: one global scope holding 131 top-level functions, documentation that has drifted from the build (stale counts, three broken links, a licence badged but absent), and balance argued by observation where the sibling project argues by simulation.

aioo

Solo creator, closed source

A run of small browser games published under a single pen name, with no repository, no licence and no real name attached. Two are audited here, and they overlap in time: the scooter-test site went from 2.5.0 to 2.8.1 in seven days (2026-11-09 → 11-15) and grew two further games along the way, while the car-test game went from 0.1.0 to 0.1.29 in four days inside that same week (2026-11-10 → 11-13), seventeen of those releases on a single day. Every release is described in an in-game changelog written for players.

The signature is tuning from data and saying so. Comments quote the pass rate that motivated each change, mark every number the government did not publish as a 'game setting', and describe a simulated pupil with a reaction delay used to sweep difficulty. The code is shipped unminified as plain ES modules, so all of that reasoning is readable in the browser.

The debt is verifiability, and it is the same in both: tests and server code are named in comments but stay private. The second debt is what speed does to shared code. The car game was forked from the scooter game, and the scooter site's own three modes share by copying — three copies of one MP4 muxer, kept in step by hand.

Steven Tsao

Solo developer + agents, live service

One online game run as a service: a domain registered on 2026-10-18 and version tags up to v57.57 a month later, with quick match, rooms, chat, replays and a bilingual interface. The credit is on the game's own sources page; there is no public repository.

The working style shows in the comments: an 'owner' is quoted giving instructions, agents are described adding content by 'read an example, draft, check, fix, submit', and fixes are justified with telemetry — a date, a count, a device. The same care extends outward: election-law windows are coded into the game, and the parody roster ships with a 235-link bibliography and a takedown contact.

Strongest on netcode and deployment hardening; weakest where nothing can be inspected — server workers, check scripts, a licence — and in a global-scope client that still ships a mode it retired.

Shanshenbu Brawl developers

Unsigned indie, closed source

An unsigned project — the site says only 'independent development' and speaks as 'we' — that went live in October 2026 and within about four weeks had ranked play, a shop, cloud saves, an Android wrapper and four separate environments. There is no repository and no licence.

The method is the opposite of tidy: everything is one 21,725-line HTML file, but that file is annotated like a logbook, with dated fixes, error counts, before-and-after measurements and the team's own security findings. Some comments are tagged as the result of an AI review, and several are signed with short handles whose nature cannot be determined.

Highest technical ambition in the audit — rollback netcode, trained opponents, procedural animation — paired with its lowest structural discipline, and a ranked ladder that seats bots as players without saying so.

Andrew Huang, MD

Individual creator, submitted for audit

One short game published under the projects section of a personal site titled 'Andrew Huang, MD — Medicine, AI & Ideas'. It is the only project in this report that asked to be here: an issue on this site's repository described the game, offered a self-assessment and invited a comparison. There is no repository; the three scripts are served unminified.

The signature is restraint. A 929-line engine that touches neither the DOM nor the network, an interface that only draws what the engine reports, and a title screen that promises to collect no data — a promise the code keeps. The subject is drawn from life: block exams, shared lecture notes, roll calls and past papers, written by someone who evidently sat them.

The debts are the ones a small solo project usually carries: no tests despite an engine built to be tested, balance set by hand, a security policy that is declared but not enforced, and credit owed — and given — for the walk-and-interact presentation and the generated illustrations.

Kōritsu Lab (Ion)

Small studio

Kōritsu Lab (効率) describes itself as a small studio founded in Taipei in 2026 that makes interactive works and tools. Its site lists six free browser games — an investing game on historical prices, a career game set in the advertising industry, this election game, an arcade cooking game, a typhoon battle-top game and a political-parody survival game — and a journal of twenty posts, each signed Ion, the studio's creator, with publication and update dates.

The studio states its practices in public: the about page says AI tools assist with code and text and that everything is reviewed before publication; a disclaimer page separates entertainment from prediction for its finance, weather and political titles; each game has its own privacy policy. For this game the journal explains the design motive (a time budget that cannot be met, a vow rewritten in red) and a lesson learned from comparing simulated and real win rates.

Judged from this one title: strong on systems design, writing volume and finish, disciplined TypeScript with a pure core, and careful, well-disclosed data handling. The recurring limit is verifiability — no public repository, tests, simulator or server code — together with a deployment that omits common security headers while publishing full source maps.
