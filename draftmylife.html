Draft My Life

A paid, AI-narrated text life-sim from age 15 to death in which the program rolls every outcome — exams, hiring, illness, death — and the language model is only allowed to write the scene; a second, fantasy chapter currently ships as a pre-written prologue.

The seven dimensions

memoryTechnical Depth 8/10

The core technical idea is a strict division of labour between program and model, enforced in code. The browser advances a structured calendar, rolls every outcome and sends one JSON payload; the request carries only messages, and a comment states that model, tools and system prompt are decided by the Worker and ignored if the client sends them (index.html:17596-17597, 10415-10417). The reply must be a forced tool call, and a validator rejects replies where the model wrote pseudo-XML into the fields (index.html:17696-17708). What comes back is then sorted into three classes: regenerate (at most once per turn), repair in code, or only log (index.html:11123, 11441). Numbers the model reports are clamped — STAT_DELTA_LIMITS and a windfall cap exist because a player can talk the model into a lottery win (index.html:1073-1101). Around that sit a real-date calendar with lunar holidays, a turn budget per age band (index.html:7390-7399), per-turn nonces so retries are not charged twice, and about twenty migration and backfill steps run on every load (index.html:5754-5776). The fantasy chapter is a separate 37-module engine with an injectable seeded RNG (fantasy/engine/rng.js:2-12) and transports passed in as arguments. Limits: the modern chapter is one 26,654-line inline script with a single global state, and the Worker, where the prompt and wallet live, cannot be read.

stadia_controllerGame Design 8/10

The design rule is written into the comments again and again: the model narrates, the program decides. Death is an annual roll of an age table times a health multiplier, and the first hit only plants a warning; the ending needs a second hit (index.html:10484-10507). Hiring is a visible sum — base 35, knowledge, network, major match, age penalties, clamped to 5–90% — and the same breakdown object drives both the roll and the on-screen explanation (index.html:4129-4152). Knowledge growth comes from an event label the model picks and a table the program rolls, with a per-stage cap on milestones (index.html:3106-3130). Each turn pairs a free-text or chosen response with a 'focus' that settles growth separately, so writing well cannot replace studying. An idle mode lets the character live offline by personality-weighted tags and never rolls death or major illness while the player is away (index.html:18557-18600). The fantasy prologue adds a world rule the validator defends — a 'forgotten' person whom only the player may name (fantasy/engine/ai.js:105-129). The limits are stated by the code itself: 307 lines carry the tag 【測試參數】 (test parameter), a header comment says a full life measured about 2,000–2,100 turns against a one-to-two-hour target (index.html:1044), and every turn costs one sheet of paid or rationed 'paper'. The quality of the generated prose could not be assessed from the artifact.

securityBackend & Security 7.5/10

This is the only life-sim in the audit with a real service behind it: a Cloudflare Worker at life-game.smile80275.workers.dev handling e-mail one-time-code accounts, a shared wallet, cloud saves, the AI proxy and NewebPay checkout. What is visible is careful. The page sends an enforced Content-Security-Policy whose connect-src lists only itself and that Worker and whose form-action lists only the payment gateway, with frame-ancestors 'none'. The checkout page keeps its own allowlist of gateway URLs (buy, snippet var FORM_LIVE = [). The recovery key was moved out of GET URLs into a header, with a dated note (index.html:1059-1060). Analytics for the fantasy chapter pass a field whitelist that drops free text (fantasy/analytics.js:39-56), and the privacy policy (version 2.1) lists these same fields, the AI provider hand-off and administrator access to saves. Comments carry numbered findings from the team's own security scan (資安H4, M6, M7, L3). Limits: the CSP allows 'unsafe-inline' because the game is inline; the session token and recovery key sit in localStorage; every missing path, robots.txt included, returns the 2.2 MB game page with status 200; the page is served with access-control-allow-origin: *; and the Worker code — where balances, rate limits and the prompt are enforced — was not readable, so those controls are taken from comments.

codeCode Quality 6/10

Two codebases with opposite habits share one domain. The modern chapter is a single index.html of 27,704 lines: about 1,800 functions in one inline script, one global let state (index.html:5345), 260 script lines longer than 300 characters, and 119 empty catch(e){} blocks. The fantasy chapter, written later, is 37 ES modules, none longer than 1,142 lines, with storage, transport, RNG and the AI call all injected (fantasy/slots.js:10, fantasy/backend.js:129, fantasy/engine/turn.js:133) — code shaped to be run under Node. What holds the large file together is annotation. Nearly every block cites a design-document section, a date and a status tag such as 【定案】 (settled) or 【測試參數】, and bug fixes name the playtest that exposed them, for example a sibling name of the wrong gender traced to a dated PDF (index.html:6296). AI-written text is escaped before it reaches innerHTML (index.html:24359-24361, 24415-24418). Some residue shows: a client-side MODEL constant that a later comment says the server ignores (index.html:1068), a function parameter immediately overwritten (index.html:5779-5780), and a naming collision avoided by comment, not by scope (index.html:18600). Nothing is minified, so these are read facts; the Worker and build scripts were not visible.

experimentTesting 4/10

No test file is served, but the shipped code refers to a test suite more often and more specifically than any other closed-source project in this audit. Comments name tests/test-54-version.mjs, which is said to check that the page version, release notes and Worker version agree (index.html:16351); tests/test-80, said to compare the legal pages with constants (index.html:5534); tests/test-84-turn-flow.mjs, said to scan for state fields missing from the undo snapshot list (index.html:18077); and tests/test-307, said to check three version strings in the fantasy page (fantasy/index.html:16). The numbering suggests a few hundred files, which is an inference. A fixture of 150 hand-labelled sentences is cited with recall and false-alarm figures (index.html:9513), and comments mention 60-run simulations and a 200,000-sample grid search for the death table (index.html:2457, 10483). The fantasy engine is visibly built for tests: a seeded generator whose first line says so (fantasy/engine/rng.js:1), a fake AI, mock transports and a shipped offline narrator for the modern chapter (index.html:17866). On the day of the fetch the Worker's /version matched the page's APP_VERSION. None of the tests can be read or run, there is no visible CI, and a request for tests/ returns the game page. Under this site's rule that caps the score at 4, and it earns the cap.

verifiedCompleteness 8.5/10

A running commercial service, not a demo. The modern chapter plays from senior high school to death, with endings, reincarnation or inheritance into a next life, a 'book of life' that turns a stage into a prose chapter, an idle mode, three save slots with cloud backup and voice input. Around it are e-mail accounts, a wallet with a ledger page, a pricing page listing one-off packs, subscriptions and a custom amount, a waitlist, referral and redeem codes, an in-game feedback channel and 'letters from the editor' with polls. There are terms of service (version 2.0), a privacy policy (2.1), refund rules, an age-rating line on every legal page, a consent gate with its own version number (index.html:5528-5548), a player guide with thirteen sections, and 178 player-facing release notes from 2026-09-29 to 2026-11-17, written under a no-spoiler rule (index.html:16349-16356). What is unfinished is also plain. The fantasy chapter is prologue-only: PROLOGUE_ONLY = true stops at 'Act One coming soon' (fantasy/engine/data.js:387), although the engine already contains files for later acts. The development-log page says entries are still being sorted. There is no robots.txt or sitemap, the interface is Chinese only, the game disables pinch-zoom, and the main page is a 2.2 MB document that also loads a 973 KB self-hosted font.

emoji_objectsOriginality 8/10

Life-sims narrated by a language model are an established idea; what is this project's own is how little it lets the model do. The model receives a roster with every relationship already scored, a calendar window it must stay inside, and a list of things that must happen this turn; it returns prose and a handful of enumerated tags, and the program does the bookkeeping. The framing is consistent and its own as well: the player is a 'writer', turns cost sheets of 'paper', the operator speaks as 'the editorial desk', and patch notes arrive as letters from the editor. The fantasy chapter has an original premise — a present-day adult waking at fifteen in a world where certain people are forgotten by everyone but the player — and a style sheet that bans specific stock phrases by name (fantasy/engine/prompt.js, snippet 不用這些套句). Compared with the two Taiwanese text life-sims already on this site, the mechanism differs in kind: yakyulife and cheerlife are client-only games with hand-written text and no server, where this one sends each turn to a paid model behind accounts and a wallet. All three roll outcomes in code and write in Traditional Chinese; nothing in the artifact states any connection between them. The fantasy opening rolls reuse the modern chapter's steps, which a comment says outright (fantasy/engine/roll.js:1).

  • A three-class check on every reply — regenerate (once per turn at most), repair in code, or only log, each with a short code that is also sent back as telemetry (index.html:11123, 11441-11520)

  • Caps against talking the model round — per-turn windfall and stat-delta limits, added because a player can persuade the model they won the lottery (index.html:1073-1101)
  • An enforced CSP and a privacy policy that matches the code — connect-src limited to the site and one Worker, and an analytics whitelist that drops free text (fantasy/analytics.js:39-56)

A referee for the storyteller

Most AI story games hand the model the pen and the dice together. This one takes the dice away and then checks the handwriting. classifyTurnOutput reads each reply and files what it finds under three headings, defined in one comment: class 1 is regenerated, at most once per turn; class 2 is fixed by the program without asking; class 3 is only recorded (index.html:11123). Class 1 includes a scene dated outside the turn's calendar window, a missing response paragraph and data field names leaking into prose. Class 3 is a list of small faults — an English word inside Chinese narration, an exam score written before results day, a character named before the protagonist has learned the name (index.html:11441-11490).

The list reads as a record of failures that actually happened. Entries cite a named playtest life and turn number, a day on which one check wrongly forced 46 rewrites and was downgraded to log-only, and a detector that was removed because saved games showed it was almost always wrong (index.html:11474, 11500, 11498). The codes are sent back with the next request, so the operator can count them. The fantasy chapter repeats the pattern in miniature with a validator that protects one rule of its world, and falls back to pre-written text when the rule is broken (fantasy/engine/ai.js:99-103).

One consequence is worth knowing as a player. On the live site the fantasy prologue does not reach the model at all: test parameters are ignored on production hosts, so the scripted narrator in mock.js — whose own header calls its text a demonstration — is what runs, drawing on a 1,096-line prologue text file marked as the confirmed final draft (fantasy/engine/mock.js:1-3, fantasy/engine/prologueText.js:1). The release notes say each prologue turn uses one sheet of paper; they do not say the text is pre-written, and the terms describe the game as one where 'the story is continued by AI'. This is a description of what the files do, not a judgement of intent.

smart_toyAI-assisted development

The artifact says a good deal. At run time the story is generated by an Anthropic model: the client still holds const MODEL = "claude-sonnet-5" (index.html:1068), a later comment says the Worker now chooses the model, and the fantasy chapter's local-test module lists claude-haiku-5-5 with a note that trial and launch use Haiku (fantasy/engine/liveai.js:8-12). The privacy policy says player text is sent to a third-party AI text service without naming it. On authorship, the comments name tools directly: 22 lines contain 使用者授權Claude全權判斷 ('the user authorised Claude to decide'), many more say 使用者同意Claude建議 ('the user agreed to Claude's suggestion'), and others cite Claude Code判斷, ChatGPT開發審閱 and claude.ai網頁版定案 (index.html:2305, 2339, 7408, 8154). These comments refer to the human as 'the user', which reads as the assistant's own voice; that the code was largely written by an AI assistant under one person's direction is an inference from that wording, not a statement in the artifact. No co-author trailers can be seen because there is no repository.

Verdict

The most elaborate life-sim in this audit and the only one run as a paid service: a language model fenced in by a program that rolls every outcome, clamps every number and grades every reply. The engineering judgement is high and the housekeeping is uneven — one 27,704-line file, tests that can only be taken on trust, balance still marked provisional, and a second chapter that so far is a scripted prologue.
