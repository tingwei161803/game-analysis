I Love Block

Seven days before a medical-school block exam: twenty-one time slots, four subjects whose weighting the game keeps secret, and nine endings that are not ranked by score — a pure seeded state engine underneath a walkable three.js campus.

Dimension by dimension

The seven dimensions

memoryTechnical Depth 6/10

Small, and built the right way round. engine.js opens by declaring itself a pure state engine — no DOM, no network, same seed plus same actions gives the same result (engine.js:1) — and the code keeps the promise. The mulberry32 generator stores its state inside the save object (engine.js:20-26), so a reloaded game continues the same random sequence, and every entry point (act, choose, buy, finish) clones the state and returns a new one (engine.js:211-212, 826-827). A single step loop turns that state into exactly one thing to show: a result, an event, the action list, the exam or the ending (engine.js:806-824). The walkable layer is 322 lines of three.js with no model files. Rooms and characters are assembled from boxes, capsules and spheres (world.js:32-51, 78-110), the lighting changes with the time slot (world.js:182-188), and click-to-move runs a breadth-first search on a 0.25-unit grid, refuses to cut corners, then straightens the path by line of sight (world.js:208-235). If three.js or WebGL fails to load, the game falls back to its card menu instead of breaking (world.js:5-10). The ceiling is scale: 1,849 lines of JavaScript in all, one week of content, no performance problem to solve, and a 1.27 MB unminified three.js loaded to draw boxes.

stadia_controllerGame Design 8/10

The week is a budget problem with hidden information. There are three slots a day, plus a fourth borrowed by staying up, paid for with sleep debt that lowers focus the next day (engine.js:62, 318-328); study gains shrink as a subject fills up (engine.js:72-76). What lifts it above a stat-raiser is the exam. Each run secretly makes one subject worth 40% and the others 20%, and also picks a decoy subject and a class-group rumour that is true only half the time (engine.js:46-55). The player can find out: listening in class once narrows it to two subjects and a second time confirms it, and past papers from a roommate or a good question in the lift reveal it outright (engine.js:425-436, 587, 730). Every one of those costs a slot or a relationship. Promises become commitments that fall due in a specific slot and can be broken at a price (engine.js:556, 570). The ending screen shows a cause-and-effect list collected during play and asks what you would change (engine.js:84, ui.js:520-536). Nine endings are picked by health, relationships and memories before score (engine.js:900-914), so a top mark with no energy left is a burnout ending, not a win. The limits: balance is set by hand with no simulation or telemetry behind it, the choice to bet on the rumour records a value nothing ever reads (engine.js:655-656), and the 'not alone' ending can only begin if you stay up on Saturday night, a condition the game does not signal (engine.js:841).

securityBackend & Security 6.5/10

There is no backend, and the page says so: 'fully offline, collects no data' is printed on the title screen, and the three shipped scripts contain no fetch, no beacon and no analytics call. State lives in two localStorage keys, every access wrapped in try/catch so private browsing still plays (ui.js:55-59), and a save that fails to load is deleted with a message rather than leaving the game stuck (ui.js:568). three.js is vendored instead of pulled from a CDN, and missing paths return a proper 404. Narrative text passes through an escape helper before it is written with innerHTML (ui.js:7). Three things hold the score down. The site's Content-Security-Policy is sent as report-only and allows 'unsafe-inline' and 'unsafe-eval', so it blocks nothing. A few values taken from the save are inserted without escaping — the exam modifier labels and the ending title (ui.js:498, 524) — which matters only to someone editing their own storage, because no URL parameter is ever read. And 'offline' is not literal: the page requests three font families from Google Fonts.

codeCode Quality 6.5/10

Three files with three jobs, each stated in its first line: a pure engine, an interface that 'only draws the engine's state and sends the player's choices back' (ui.js:1), and a world module that reports which spot was touched. The engine exports itself for Node as well as the browser (engine.js:928). Events are uniform, close to data — a build function returning text and choices, each choice a small state transition — which is how 33 of them fit in about 400 lines. The separation leaks in a few places: the interface re-derives the study-gain formula to show a preview instead of asking the engine (ui.js:360 against engine.js:73), the sprint minigame's difficulty is decided in the interface (ui.js:448), and the two questions asked during the exam are authored there too (ui.js:483-491). There is residue as well: an unexported view function (engine.js:802), flags that are written and never read (sprain, momLater, overslept, proxy), classroom seats naming characters that do not exist (world.js:127), and a night slot encoded as 2.5 that the interface has to Math.floor around (engine.js:352, ui.js:134). Lines are packed tight — 49 of them run past 300 characters — and the modules talk through window globals rather than imports.

experimentTesting 2/10

Nothing ships and nothing is referenced: no test file, no harness, no CI, and no comment naming one; requests for package.json and a tests folder return 404. This is the one dimension where the submitter's own assessment and this reading agree completely. What can be said in its favour is that the engine is shaped for tests it does not have — pure functions over a plain object, a seeded generator, a Node export, and a window.__game handle that exposes the live state (ui.js:597). A few dozen lines could replay a seed and assert an ending, or sweep random play to confirm that all nine endings are reachable. None of that exists in what is served.

verifiedCompleteness 7.5/10

A complete short game. A title screen with continue, a full week through to an exam sequence and an ending, a gallery with nine endings and sixteen collectible memories, a notes panel for promises and exam intelligence, a log of the week and a help sheet. There are two ways to play — walking the dorm, classroom and campus, or a card menu — switchable at any time, with keyboard, number keys and touch all handled (ui.js:573-587, world.js:301-317). Fifteen scene illustrations and eight portraits are preloaded behind a progress bar; sound is nine synthesized cues with a remembered mute toggle. Reduced-motion is respected in both script and stylesheet. What is missing: music, any way to see or share a seed (the 'replay the same week' button is its only use, ui.js:537-540), a version number or changelog, any language but Chinese, and more than one week of content.

emoji_objectsOriginality 7/10

The setting is its own: a fourth-year medical student, shared lecture notes counted in pages, a professor who 'accidentally' mentions exam questions at the Friday review, past papers handed down by a senior. The frame is familiar — a week of time slots spent raising stats is a long-established life-sim pattern — and the walk-up-and-interact presentation is openly credited to another creator's on-call ward simulator, both in the code and in the help sheet (world.js:2, ui.js:431). What is new sits in the middle: an exam whose weighting has to be investigated, with a decoy and an unreliable rumour, and an ending that is a causal recap rather than a grade. The illustrations are AI-generated, which the help sheet states.

  • Pathfinding in under thirty lines — grid breadth-first search, no corner cutting, line-of-sight straightening, and a re-plan when stuck (world.js:208-235, 272)
  • 'Collects no data', and the code agrees — no network call in any shipped script, and storage access wrapped so private browsing still works (ui.js:55-59)

trending_downWeaknesses

  • Rules leak into the interface — a duplicated gain formula, the sprint threshold and the exam questions all live in ui.js (ui.js:360, 448, 483-491)

A self-assessment, checked

This project arrived as a submission. An issue on this site's repository described the game, predicted that testing and backend security would be its weakest dimensions, and asked where a code-level reading would differ. There is no public repository, so — as with the three shipped-artifact projects before it — the files the site served were read instead, on 2026-11-18. All three scripts are unminified.

On testing the prediction holds exactly: nothing ships and nothing is referenced. On backend and security it does not. A game with no server, no network calls and no input taken from a URL has very little to attack, and it handles its one storage mechanism with care; the deductions are for a policy header that is not enforced and a few unescaped values, not for exposure. That dimension lands mid-table, not at the bottom.

The gap the submission did not predict is elsewhere. After testing, the lowest score is technical depth — not because anything is done badly, but because 1,849 well-separated lines have not yet had to solve a hard problem. And the strongest is design, on the strength of one idea: an exam whose weighting you have to find out for yourself.

smart_toyAI-assisted development

The help sheet states that the illustrations were made with GPT image generation, following the style of the original concept art (ui.js:431). Nothing in the shipped files says how the code was written: there is no tool name, no co-author line and no process vocabulary in the comments, which are short Chinese section labels. The submission describes the code as original. With no repository and no history, this audit can neither confirm that nor add to it.

Verdict

A short life-sim that does the unglamorous part properly — a pure, seeded engine kept apart from its interface — and has one genuinely good design idea in an exam whose weighting must be investigated. It is one week long, balanced by hand, and entirely untested despite being unusually easy to test.
