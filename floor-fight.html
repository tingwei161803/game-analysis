Overview / Steven Tsao

Floor Fight

A 5v5 brawl on the floor of Taiwan's Legislative Yuan: relay documents, push the ballot box, hold the Speaker's rostrum, or knock out the opposing whip three times. Twenty-four parody characters drawn entirely in Canvas vectors, with online rooms that run the same simulation server-side on Cloudflare Durable Objects.

Dimension by dimension

The seven dimensions

memoryTechnical Depth 8.5/10

The deepest engineering in this audit, and most of it is netcode. The three big shipped files open with a header saying they were generated from numbered source parts by make-sim.cjs — TypeScript global scripts with the types stripped and concatenated by a home-made tool, no bundler — and the comments say the room runs that same source as sim.generated.mjs (i18n.js:9-10), so browser and server share one rule set instead of two. The client sends input every 33 ms or on change (room.js:7), predicts its own swings locally and records them for reconciliation (room.js:1355-1372), and extrapolates everyone else along their last velocity using the server's count of 1/60 s steps since the previous report (room.js:1083-1090). Replays store state, never input: fixed-length numeric rows, delta-packed, capped at 280 KB and one hour (replay-format.mjs:2-16). Rendering is one 2D canvas with a 1600×1200 world and no sprite sheets — there are seven drawImage calls across the three main files, all for UI frames. The one soft spot: the client steps on variable dt capped at 35 ms (game.js:11629-11645) while the room steps at a fixed 1/60 s.

stadia_controllerGame Design 8/10

Four ways to win, all live at once: nine documents relayed, forty cumulative seconds on the rostrum, the ballot box pushed to the far end, or the enemy whip's three lives (team.js:60-178). That is a real strategic surface — a team losing the brawl can still win the relay. Match point is modelled as a state, not an event: it arms at 7 documents, 31 seconds or 0.6 of the box track, and the box has to fall back to 0.5 before it disarms (team.js:148-151), so the tension does not flicker. Numbers are deliberately lopsided toward humans — a real player takes 0.38× damage (0.28× during onboarding) and moves at 205 against a bot's 155 — which is honest tuning for a game most people play against bots. Series are best of three. What the shipped code does not show is measurement: unlike YaKyoLife's Monte Carlo or the simulation runs quoted in the other fighter in this batch, no win-rate distribution backs the thresholds.

securityBackend & Security 7.5/10

The best deployment posture in this audit, scored with a discount because the server code itself is not visible. What can be checked from outside is strict: a CSP with default-src 'self', one inline script admitted by sha256 hash, frame-ancestors 'none' and object-src 'none'; COOP same-origin; a fully closed Permissions-Policy. Only four innerHTML writes exist in the whole client, all fed by static strings or the site's own translation catalogue. Analytics are PostHog with no cookies and no session recording (stats.js:1-4). Replay uploads are bounded in size, duration and id format, and fail without affecting the match (replay.js:216-233). Feature flags live in KV and flip without a deploy (/room/flags). The part that has to be taken on trust: score-worker.mjs, the chat worker and the design worker are named in comments but never shipped to the browser, so the server-authoritative claim rests on comments and on behaviour, not on a read of the code.

codeCode Quality 7/10

Comments are the strongest feature of the codebase: they explain *why*, cite a version tag, and frequently carry a telemetry number. The top of index.html records that PostHog logged about 150 sessions of "Can't find variable: i18n" between 2026-10-25 and 10-29, all iOS WebKit back/forward loads, and that the fix is the inline script the CSP hash admits (index.html:10-15). compat.js:1-4 adds an Object.hasOwn polyfill because two players on old iPhones hit it inside in-app browsers. The structure underneath is less disciplined: everything is a classic script in one shared global scope, 29 <script> tags loaded in order with their own unrelated ?v= values (game.js?v=126, room.js?v=123, boot.js?v=57.28), and later files hook earlier ones by reassigning globals (replay.js:20-30, look.js:32-45). And the shipped game.js still carries the wave-and-boss campaign that the sources page says was removed in v56.8.

experimentTesting 4/10

The hardest dimension to score, because the evidence is real but second-hand. Comments name at least ten check scripts — content-check (cited 28 times), team-sim.cjs, replay-box-check.mjs, compat-check.cjs, chat-check.cjs, i18n-check.mjs, score-worker-check.mjs and others — and the code is visibly built to be checked: when navigator.webdriver is true the hero and map are pinned so captures are reproducible (game.js:3896-3899), and window.musou.snapshot() exposes state to a harness. One check has a documented origin: v56.8 raised the winning document count from 8 to 9, the replay validator's bound stayed at 8, every documents-win replay was refused until v56.26, and replay-box-check.mjs now keeps the two equal (replay-format.mjs:13-15). But none of those scripts ship, nobody outside can run them, and there is no way to tell whether a CI gate exists. This is scored above every project with no tests and below any project whose tests can be read.

verifiedCompleteness 9/10

A live service rather than a demo. Both languages are complete (two 1,105-line catalogues), with quick match, private rooms with unambiguous room codes, spectating, a site-wide chat, a replay gallery, share cards, a local-only career record (record.js:1-7), outfits and four maps in rotation. The /sources page is the unusual part: 77 entries and 235 outbound links documenting where each character's props and moves come from, with a correction and takedown contact. The public stats endpoint reported about 94,000 matches played on the audit date. The gaps are small — no PWA manifest or service worker — and the documentation has started to drift from the build: the sources page still describes eighteen characters in three groups of six, while the shipped roster lists twenty-four.

emoji_objectsOriginality 7.5/10

The multi-objective structure is borrowed and says so: the sources page credits the three-route win condition, escorting and series play to Killer Queen Arcade, and states that no art, audio, code or maps were taken. What is its own is everything the borrowed frame is filled with — a legislative chamber as an arena, the three readings of a bill as three lives, props researched to the point of needing a bibliography — and one piece of design no other project here attempts: the game's behaviour is constrained by election law in code. Parody names are used in play; real names appear only on the sources page.

trending_upHighlights

  • One source, two simulations — the browser build and the room's sim.generated.mjs are generated from the same TypeScript parts by a home-made make-sim.cjs, so client and server cannot drift on rules
  • Prediction plus extrapolation — own swings are predicted locally, everyone else is extrapolated by the server's count of 1/60 s steps since the last report (room.js:1083-1090, 1355-1372)
  • Replays that store state, never input — delta-packed numeric rows with no socket identities or user text, bounded at 280 KB and kept 90 days (replay-format.mjs:2-16)
  • Election law as a code path — ELECTION_QUIET and ELECTION_DAY windows hide anything readable as a popularity count and pull a campaign-themed map on polling day (game.js:3-9)
  • Fixes argued from telemetry — comments carry the date, count and device behind each workaround, e.g. ~150 sessions of an iOS back/forward failure (index.html:10-15)

trending_downWeaknesses

  • Source not public, no licence — no repository, no LICENSE, no source maps; every claim here is checked against the shipped build only, and the server workers cannot be checked at all
  • A removed mode still ships — the wave-and-boss campaign dropped in v56.8 is still in game.js (28-70, 3914-3925), and look.js:8 still describes it as usable
  • One global scope across 29 scripts — an 11,730-line generated game.js, load order as the only contract, and later files patching earlier ones by reassigning globals
  • Hand-maintained cache-bust tokens — each script tag carries its own ?v= on an unrelated numbering (?v=126, ?v=123, ?v=57.28)
  • Stale counts in comments and docs — the roster is 24, while the sources page says eighteen, outfit.js:4 says twenty-one and game.js:3897 says fifteen

Election law, written as code

The first lines of game.js are not about the game. They define two time windows around Taiwan's local elections of 2026-11-28 and cite the statute for each: Article 53 of the Public Officials Election and Recall Act, which bars publishing polls in the ten days before the vote, and Article 56, which bars campaign activity on polling day (game.js:3-9).

The windows change behaviour. During the quiet period nothing that could be read as a count of who is popular is shown; on polling day a campaign-themed map is taken out of rotation. A separate rule on the boss roster guarantees that no party is the default enemy and that two rival candidates never face each other as final boss (game.js:264-268). The comments note that the server worker carries the same dates.

This audit's date, 2026-11-17, falls within hours of the quiet window opening, so the page described here will behave differently for the eleven days that follow. It is the only project in this report where a legal constraint is a first-class input to the design — and where a parody of living public figures ships with a bibliography and a takedown contact rather than a disclaimer.

smart_toyAI-assisted development

No commit history to read and no tool named, but the shipped comments describe an agent-driven workflow in the third person. The phrase "the owner" appears 87 times across the JavaScript, usually quoting a spoken instruction and then explaining how it was implemented. lab.js:10 describes a content pipeline as "the way the developers' agents added content: read an example, draft, check, fix, submit". Which model or tool did the work is not stated anywhere. Separately, the game itself contains an AI feature — a weapon designer built on Cloudflare's Agents SDK and Workers AI — currently switched off by the lab flag.

Verdict

The most complete piece of engineering in this audit and the first one read without a repository: a server-simulated online brawler with prediction, a state-only replay format, a hardened deployment and comments that double as an incident log. Its ceiling is set by what cannot be seen — the server workers, the check scripts, a licence — and by a global-scope structure that still ships a mode it says it removed.
