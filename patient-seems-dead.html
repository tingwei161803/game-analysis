My Patient Seems a Little Dead: A Rookie Nurse's Diary

One eight-hour shift on a haematology-oncology ward: four to sixteen beds, alarms in three grades, your own water and stamina running down, and a handover quiz at the end built from what actually happened — all in a single 2.3 MB HTML file that makes no network calls.

The seven dimensions

memoryTechnical Depth 6.5/10

The whole game is one file, and under the 1 MB of base64 art and the 600 KB of three.js it is a schedule-driven event engine. A 40 ms interval (index.html:12072) advances a game clock at three real seconds per game minute (index.html:2199, 12110); each minute fires due schedule entries, delayed follow-ups, lab reports and deadline checks (index.html:12128-12152). Each patient carries a schedule whose entries give an event id plus time or window, a probability, and optionally oneOf or excludeShifts; the shift builder resolves them against shared templates (index.html:4004-4062, 9636-9652). Newer events describe their consequences as data — outcomes, deadlineMinutes, onExpire (index.html:3183-3189). Movement is Dijkstra over a hand-built graph of hall, door and room nodes (index.html:10085-10200). The 3D ward is the neat part: an orthographic camera tilted 52 degrees whose floor is affine-aligned with the 2D stage percentages (index.html:13402-13410), so clicks, cards and navigation needed no change; three.js and the scene sit in text/plain script tags and are injected after load (index.html:13870-13879), falling back to the 2D image if WebGL fails (index.html:13828). Alarms are synthesised with Web Audio in three grades (index.html:2113-2150). The limits are structural: one global gameState, 70 unseeded Math.random calls, no modules, and nothing computationally hard.

stadia_controllerGame Design 8/10

It models the nurse, not the patient. No patient has continuous vitals; clinical state is a deck of event cards, and taking vital signs rolls a seven-row table (index.html:3174-3182 — 8% hypertension down to 0.2% arrest) that each case can reweight through vitalRisk (index.html:3476-3484). What the player manages is their own stress, stamina, hydration and backlog of unwritten records, alongside patient safety and a senior colleague's goodwill; any of four thresholds ends the shift (index.html:12365-12372). The clinical content is specific. Medication is on time within an hour either side of the due time (index.html:11466, 9820-9827). Lab reports are generated with five grades, and a critical value handled as routine has a 40% chance of becoming the matching emergency 45 minutes later (index.html:11017-11023, 11090). One order is a trap: insulin 1000 U, which the debrief explains is a whole vial and must be queried (index.html:11148). The end of the shift is a per-bed handover quiz assembled from that shift's own events, with trivia and a false 'all stable' as distractors (index.html:11546-11570), followed by a review that grades each decision against the options' safety values and explains it (index.html:11486-11495, 11141). An intern shift stages a priority drill (index.html:9806-9813). The limits: 'correct' is whatever has the highest safety number, thresholds are labelled as game settings (index.html:11009), and the README records a stage where a bot fainted in five of six day shifts.

securityBackend & Security 5.5/10

There is no backend. The Worker's configuration contains only a static-assets entry (wrangler.jsonc: "directory": "."), /api returns 404, and the script has no fetch, XHR, beacon, WebSocket or analytics call and loads nothing from another origin — fonts, art and three.js are all inside the file. The one call that can leave the page is navigator.share for the result image, started by the player (index.html:13220). State is six localStorage keys, each access wrapped in try/catch, and a damaged collection falls back to an empty one (index.html:9211-9220); the achievements screen tells players that records stay on this device. The nickname reaches the page through innerText (index.html:9851, 13247) and the decision review escapes its fields (index.html:11672); the only URL input is a regex test for preview=1 (index.html:8978). The feedback form says plainly that it sends nothing (index.html:13062). Two things hold the score down. The home page is served with no Content-Security-Policy, HSTS, X-Content-Type-Options or framing header. And because the asset directory is the project root, the deployment also answers 200 for README.md, wrangler.jsonc, .gitignore and .git/HEAD; nothing sensitive was seen in the files read, and the .git contents were not fetched. Missing paths return a proper 404.

codeCode Quality 5/10

Readable and commented, but built in layers that were never merged. Two mechanisms for 'what happens next' coexist. Newer events declare outcomes with delayMin on the game clock; older ones are branched by hand on option flags inside a 250-line stretch of selectOption and scheduled with wall-clock timers — a 15-minute glucose recheck is setTimeout(…, 15000) (index.html:11774-11782), which ignores both game speed and pause. Stamina loss is rescaled after the fact by comparing with the previous value (index.html:12356-12360) instead of at each source. Endings are identified by matching their display text with regular expressions (index.html:9154-9176, 11641-11647), so the English build has to translate the patterns too. The glossary is patched at start-up by FIX, DROP and ADD lists (index.html:12846-12913). A comment says admissions are 'currently false' two lines above enabled: true (index.html:12401, 12403), and openMemorial is defined and never called (index.html:8983). There are 26 empty catch blocks and 85 inline onclick handlers. On the other side: the template resolver is a clear single point (index.html:4004-4062), tuning constants are named and explained, and the 62 commits are small with descriptive messages. The larger issue is that the repository holds build output — the README says to edit data/patientPool.json, src3d/scene3d.js and scripts under tools/, none of which are published.

experimentTesting 3.5/10

The current tree has no tests and no CI, but the history shows that testing happened. One file was committed and then removed three commits later with the message that it was added by mistake and that tests are kept only in a zip (f1a49ae); it can still be read with git show 26f8efe:tests/smart_playtest.py. It is a 156-line Playwright script that plays whole shifts through the real page under a virtual clock: it buys items, drinks, writes records, answers events by the options' safety values under three skill levels (expert, average at 75%, rookie at 45%), and fills in the handover. It wraps ringRoomAlarm, handleEventExpiry and triggerEndShift to log every event, flags a frozen clock or an event with no enabled option, and collects page errors. It asserts nothing about outcomes; it is a balance probe and a soft-lock detector. The README names seventeen further scripts (schedule_check.py, vital_check.py, ward_check.py, discharge_check.py and others) and quotes bot results used for tuning — for example 36 runs in which the dehydration ending fell from 13 to 3. None of those scripts could be read, so they are counted as named, not as evidence. The page keeps a gfxForce2D switch 'for automated tests only' (index.html:13866).

verifiedCompleteness 8.5/10

A finished, replayable game with more surrounding material than most entries here. Four shifts — intern with four beds, day with eight, evening with twelve, night with sixteen (index.html:2211-2215, 11322) — draw from 35 written cases carrying 653 schedule entries, each with history, family, personality and nursing notes shown in an unlockable casebook. There are 143 lettered options across the event tables, 22 catalogued endings (index.html:9154-9177), 29 titles, family thank-you cards, a searchable glossary, first-shift tips per shift, a pre-shift shop with twelve items, admissions and discharges as multi-step chains, two-hourly night rounds, keyboard shortcuts, separate portrait, landscape and desktop layouts, a reduced-motion rule (index.html:1178), a 1080×1920 result card, and a complete English build generated from the Chinese one. A disclaimer sits on the start screen (index.html:1680), in the meta description and on the share card. What is missing or rough: a shift cannot be saved part-way, the feedback button is hidden (index.html:1664), there is no licence file, no version number in the page, the salary image stays in Chinese in the English build by the README's own account, and the README still opens with an older title and a folder table for files that are not in the repository.

emoji_objectsOriginality 7.5/10

The subject is its own: a haematology-oncology ward seen from the newest nurse, written in the ward's working slang — bedsores as '杯叟', 'new pe', the senior who is 'a god at drawing blood' — with jokes that only land if you have worked a shift, such as a results screen that converts what is left of the day's pay into the years needed to buy a flat (index.html:13268-13276). The frame is familiar: timed alarms, lettered choices and resource bars are standard management-sim furniture, and a comment describes the 3D look as modelled on a well-known co-op kitchen game (index.html:13402). What is new is in the mechanics drawn from the job: hydration and unwritten records as resources, a medication window, a prescribing error the player is expected to refuse, and handover as a scored final step. Neither the page nor the README mentions any other medical simulator as a source. The README's own to-do list does record that an earlier start screen was too close in layout and copy to another title, and a later entry says it was replaced with an original name and design; the same list discusses art made in the manner of a named illustrator, whose name does not appear in the game. Where the embedded art and the salary-table photo come from is not stated.

A README for a project you cannot see

The public repository tracks five files: two HTML pages, two images and a 332-line README. The README, though, describes a much larger project: a patient table in data/patientPool.json that a Python script embeds into the page, a 3D scene in src3d/scene3d.js embedded the same way, a translation pipeline under tools/i18n/, a design handbook in docs/, an archived React version, and a test folder. None of these were published. What is public is the output of that pipeline, committed after each change.

The tests show the gap most clearly. The README names eighteen test scripts and reports what the play-testing bot found. Exactly one of them ever reached the repository, and it was deleted three commits later with a message saying it had been added by mistake and that test files are kept only in a zip. Because git keeps history, that one file is still readable, and it is a real whole-shift bot, not a stub.

For a reader this cuts both ways. The page is unminified and the history is open, so everything that runs can be read. But the scores for code quality and testing here describe the published artifact, and the working project behind it — the part that would show how the data is maintained and how much is checked — is described, not shown.

Verdict

A nursing shift simulator whose best ideas come straight from the job: your own water and paperwork as resources, an order you are meant to refuse, and a handover that is marked. It is complete, private and generous with explanation. The code is a single file patched in layers, the repository holds only the build output, and the testing that the README describes is not there to read.
